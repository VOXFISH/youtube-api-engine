# 섀도맵 성능 비교

측정일: 2026-11-16. 현재 엔진의 동일한 Release 실행 파일에서 섀도맵·BVH 컬링·깊이 캐시 스위치를 전환했다. 이전 버전 바이너리와의 비교는 아니다.

이 보고서는 광원별 선택 무효화 구현 전의 실험이다. 이후 구현 및 동적 전역/선택 갱신 비교는 [변경 경계 BVH 실측](shadow-invalidation.md)에 있다. 재현용 `RiceShadowBenchmark`는 이 문서의 기존 전역 무효화 정책을 명시적으로 선택한다.

## 측정 결과

NVIDIA GeForce RTX 4060 Ti, OpenGL 3.3 / NVIDIA 610.88에서 실행했다. CPU 식별 문자열은 `AMD64 Family 25 Model 97 Stepping 2, AuthenticAMD`다. 아래 표는 완료 시간 p50(ms)이며 숫자가 작을수록 빠르다.

- 전체 갱신 대비 BVH+캐시의 속도비(전체 갱신 시간 / 최적화 시간)는 정적 **5.44배**, 물체 이동 **3.21배**, 광원 하나 이동 **4.98배**다. 정적 캐시가 깊이 패스를 생략해도 섀도 샘플링과 캐시 확인은 남는다. 그림자 끄기 대비 최적화된 그림자의 추가 완료 시간은 각각 약 **1.52ms / 19.65ms / 2.58ms**다.
- 물체 이동에서는 깊이 43면을 계속 갱신하지만 제출 수가 129,000회에서 평균 14,870.25회로 **88.47% 감소**했다. 캐시만 적용한 모드도 43면을 그려 깊이 재사용 이득이 없다.
- 광원 하나 이동에서는 캐시가 갱신을 8광원/43면에서 1광원/6면으로 줄인다. BVH까지 적용하면 제출 수는 129,000회에서 평균 1,718.3회로 **98.67% 감소**한다. 캐시만 적용했을 때의 18,000회보다도 **90.45% 감소**한다.

### 다음 최적화의 우선순위

1. 움직이는 caster의 이전/현재 경계와 포인트 광원 영향 범위를 이용해 **영향받은 광원만 무효화**한다. 현재는 caster 하나의 변경도 장면 revision을 바꾸어 모든 광원을 갱신한다. 물체 이동 장면의 남은 비용을 줄일 후보이나 이번에 구현하거나 개선율을 측정한 것은 아니다.
2. 장면 전체를 덮는 방향광은 BVH가 제출 수를 줄이지 못한다. 이러한 뷰의 전체 순회 전환을 검토할 수 있다. 현재 결과만으로 항상 빠르다고 단정하지 않는다.
3. 저비용 설정에서는 동시에 그림자를 만드는 포인트 광원 수·범위를 제한한다. 포인트 하나가 깊이 6면을 필요로 하며, 정적 캐시가 적중해도 메인/반사 색상 패스의 그림자 샘플링 비용은 남는다.

## 검증 결과

기본 37조건과 반사 2조건, 총 19,500개 반복 측정 프레임의 갱신 면 수·작업량 검사가 통과했다. 그림자를 켠 모드 사이의 이미지 비교 117건은 모두 **픽셀 완전 일치**했다(허용 오차 1로 검사했지만 실제 최대 차이 0). `off`는 그림자가 달라야 하므로 동등성 비교에서 제외한다. `ShadowRender` 회귀 테스트에는 방향광·포인트의 모든 컬링/캐시 조합, 캐시 적중 시 카운터 초기화, 실제 드로/인스턴스 수, 알파·비활성 caster 제외 검증을 추가했다.

최신 Release 빌드에서 `ShadowRender`, `LightRendering`, `CubeInstancing`, `SceneSpatial` 회귀 테스트 4개가 모두 통과했다. 원시 CSV로부터 기본 실험의 p50/p95·카운터를 독립 재계산한 결과도 저장된 요약과 일치했다.

## 실험 조건

- 메인 뷰 640×360, 섀도맵 각 면 512×512, 기본 바닥 활성. 에디터 UI·화면 출력·물리 시뮬레이션은 제외한다.
- 물체 100 / 1,000 / 3,000개를 80×80 영역에 결정적으로 배치한다. 80%는 인스턴싱 가능한 큐브, 20%는 사각형이며 크기·높이·회전이 다르다. 광원은 방향광 1개, 포인트 1개, 방향광 1 + 포인트 3개, 방향광 1 + 포인트 7개다. 포인트 범위는 32다.
- 정적, 물체 10% 이동, 광원 하나 이동을 각각 실행한다. 혼합 광원에서는 포인트 하나만 이동하며, 방향광 단독에서는 방향을 바꾼다. 카메라만 움직이는 1,000개/혼합 4광원 조건도 추가한다.
- 각 조건/모드당 준비 3프레임 후 20프레임을 측정하고 5회 반복한다. 모드당 표본 100개, 기본 37조건 × 5모드 = 18,500개 측정 프레임이다. `(repeat + slot) % 5` 순서로 각 모드가 실행 위치 5곳에 한 번씩 오게 했다. 각 모드는 같은 모션 프레임을 재생한다.
- 모든 모드에서 월드 행렬·경계·장면 스냅샷 캐시와 큐브 인스턴싱을 유지한다. 여기서 **캐시**는 섀도 깊이맵 재사용을 뜻한다. 월드/경계 캐시 자체의 유무를 별도로 비교하는 실험은 아니다. 앞선 비교는 [장면 공간 캐시 실측](scene-spatial.md)에 있다.

| 모드 | 그림자 | 깊이 뷰 BVH 컬링 | 깊이맵 재사용 |
|---|---|---|---|
| `off` | 끔 | 깊이 패스 없음 | 해당 없음 |
| `full` | 켬 | 끔 | 끔, 매 프레임 전체 갱신 |
| `bvh` | 켬 | 켬 | 끔 |
| `cache` | 켬 | 끔 | 켬 |
| `optimized` | 켬 | 켬 | 켬 — 엔진 기본 설정 |

컬링을 꺼도 장면 BVH 준비·refit 비용은 남는다. 따라서 `full → bvh`는 BVH 유지 비용을 양쪽에 포함한 **후보 질의·제출 감소의 효과**다. 반사가 없는 `off`는 공간 스냅샷 준비를 생략할 수 있으므로 on/off 차이에는 이 준비 비용도 들어간다.

표의 시간은 프레임 시작부터 GPU 완료(`glFinish`)까지 기다린 **완료 시간의 중앙값(ms)**이다. 파이프라인이 겹치는 실제 게임 FPS로 환산하지 않는다. 원본에는 CPU 제출 구간과 `GL_TIME_ELAPSED` 구간의 p50/p95도 기록했다. CPU 구간은 모션·뷰포트 준비·렌더 제출을 포함하고, GPU 질의는 `renderer.Render`만 감싸므로 뷰포트 준비/clear는 제외한다. GPU 질의에는 CPU 명령 공급을 기다리는 시간도 들어가 순수 GPU 연산 병목을 판정할 수 없다. 분위수는 nearest-rank 방식이다.

첫 Render는 각 조건의 `phase=cold` 행으로 따로 보존하고 아래 반복 통계에서 제외했다. 이 값은 지연 GPU 리소스 준비를 포함하지만 장면/렌더러 생성자와 프로그램 시작은 제외하므로 앱 시작 시간은 아니다.

## 원본과 재현

위 분석과 측정 요약은 보존하고, 원시 CSV·이미지·환경 기록은 발표 폴더 정리 과정에서 제거했다. `Tests/Benchmarks/ShadowBenchmark.cpp`로 기본 실험과 반사 실험을 다시 실행할 수 있다. 각 실행은 `summary.csv`, `frames.csv`, `parity.csv`, `metadata.txt`를 출력하며, 새 결과는 개발용 `Engine/Cache/benchmarks/shadows`에 저장한다.

```powershell
cmake --build Engine/Cache/local --config Release --target RiceShadowBenchmark RiceShadowRenderTests --parallel 4
ctest --test-dir Engine/Cache/local -C Release -R "ShadowRender" --output-on-failure
./Engine/Cache/local/bin/Release/RiceShadowBenchmark.exe Engine/Cache/benchmarks/shadows/core 20 5
./Engine/Cache/local/bin/Release/RiceShadowBenchmark.exe Engine/Cache/benchmarks/shadows/reflection 20 5 reflection
```

출력 디렉터리 뒤 인자는 측정 프레임 수, 반복 수, 선택적인 조건명 부분 문자열이다. 예를 들어 `3000_mixed8`은 3,000개/8광원 세 조건만 실행한다. `reflection` 조건은 필터를 명시할 때만 실행한다. 시간은 자동 CTest 합격 기준으로 쓰지 않는다. 기본 벤치마크와 반사 벤치마크, 빌드/테스트는 순차 실행한다.
