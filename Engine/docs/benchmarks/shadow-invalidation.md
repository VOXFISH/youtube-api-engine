# 변경 경계 BVH를 이용한 광원별 섀도맵 갱신

측정일: 2026-11-16. `SetShadowSelectiveInvalidationEnabled(true)`가 기본값이다. 움직인 물체의 이전·현재 경계를 이용해 영향받은 포인트 광원만 깊이맵을 갱신한다. 방향광은 caster 변경 시 보수적으로 다시 그린다.

## 결과

국소 이동에서는 갱신할 깊이 면이 줄었고, 모든 광원이 영향을 받는 경우에는 절약이 없었다. 아래는 **프레임 완료 시간(ms)**이다. 속도비는 전역 p50 / 선택 p50이며 1보다 크면 선택 갱신이 빠르다. 에디터 FPS나 순수 GPU 연산 시간은 아니다.

| 물체 / 광원 / 이동 | 전역 p50 | 선택 p50 | 속도비 | 전역 p95 | 선택 p95 | 깊이 면 수 |
|---|---:|---:|---:|---:|---:|---:|
| 100 / 분리 포인트 4 / 국소 10% | 1.24 | 0.90 | 1.380× | 1.91 | 1.45 | 24 → 6 |
| 100 / 분리 포인트 8 / 국소 10% | 1.49 | 0.96 | 1.544× | 2.21 | 1.36 | 48 → 6 |
| 100 / 방향 1 + 분리 포인트 7 / 국소 10% | 1.46 | 1.03 | 1.420× | 2.02 | 1.36 | 43 → 7 |
| 1,000 / 분리 포인트 4 / 국소 10% | 8.33 | 6.93 | 1.203× | 11.51 | 10.01 | 24 → 6 |
| 1,000 / 분리 포인트 8 / 국소 10% | 10.57 | 9.00 | 1.175× | 13.03 | 11.44 | 48 → 6 |
| 1,000 / 방향 1 + 분리 포인트 7 / 국소 10% | 10.23 | 10.14 | 1.008× | 13.63 | 13.63 | 43 → 7 |
| 3,000 / 분리 포인트 4 / 국소 10% | 32.59 | 32.31 | 1.009× | 41.50 | 43.47 | 24 → 6 |
| 3,000 / 분리 포인트 8 / 국소 10% | 34.08 | 28.51 | 1.195× | 40.50 | 35.25 | 48 → 6 |
| 3,000 / 방향 1 + 분리 포인트 7 / 국소 10% | 49.94 | 44.98 | 1.110× | 66.11 | 54.17 | 43 → 7 |

- 3,000개·분리 포인트 8개에서 깊이 패스가 **48→6면(87.5% 감소)**, 제출 caster는 **3,000→375회**가 됐다. 완료 시간 중앙값은 **34.08→28.51ms**, 약 **16.35% 감소(1.195배)**였다.
- 3,000개·혼합 8광원에서는 방향광을 계속 갱신해 **43→7면**, 완료 시간은 **49.94→44.98ms**, 약 **9.94% 감소(1.110배)**였다.
- 이 결과의 기존 방식도 이미 BVH 컬링·깊이 캐싱·월드/경계 캐시·인스턴싱을 사용한다. 따라서 이번 속도비는 이전 보고서의 ‘컬링·캐시 없음’ 대비 속도비와 다르다.

### 손해나 작은 이득이 가능한 조건

| 물체 / 광원 / 이동 | 전역 p50 | 선택 p50 | 속도비 | 전역 p95 | 선택 p95 | 깊이 면 수 |
|---|---:|---:|---:|---:|---:|---:|
| 1,000 / 분리 포인트 8 / 분산 10% | 14.21 | 13.30 | 1.069× | 17.94 | 15.95 | 48 → 48 |
| 3,000 / 분리 포인트 8 / 분산 10% | 39.49 | 40.45 | 0.976× | 46.15 | 47.37 | 48 → 48 |
| 3,000 / 겹치는 포인트 8 / 국소 10% | 75.09 | 74.61 | 1.006× | 99.65 | 97.78 | 48 → 48 |
| 3,000 / 방향광 1 / 국소 10% | 36.85 | 37.41 | 0.985× | 44.21 | 43.56 | 1 → 1 |
| 1,000 / 분리 포인트 8 / 정적 | 8.50 | 9.35 | 0.909× | 12.23 | 12.06 | 0 → 0 |
| 1,000 / 분리 포인트 8 / 광원 밖 10% | 13.83 | 10.73 | 1.289× | 17.09 | 13.12 | 48 → 0 |
| 1,000 / 방향 1 + 분리 포인트 7 / 국소 10% + 반사 | 31.84 | 27.32 | 1.166× | 36.98 | 32.55 | 43 → 7 |

분산 이동은 모든 포인트 광원의 영역에서 물체가 움직여 48면을 그대로 그린다. 3,000개 조건에서 선택 갱신은 약 **2.42% 느렸다**. 방향광 단독도 깊이 작업을 줄이지 못하며 약 **1.53% 느렸다**. 겹치는 8광원 조건의 약 0.6% 차이는 성능 개선으로 해석하지 않는다.

정적 조건은 양쪽 모두 깊이 0면이다. 선택 모드의 8.50→9.35ms 차이는 개별 기록 비교 비용과 측정 변동을 포함하며, 정확한 추적 오버헤드를 분리 측정한 값은 아니다. 정적 프레임에는 변경 경계 BVH를 만들지 않지만 공개 transform/컴포넌트 변경을 감지하는 스냅샷 수집·비교는 계속 수행한다. 이번 변경은 전체 스캔을 O(log N)으로 바꾸는 최적화가 아니다.

광원 밖의 물체만 움직일 때는 48면을 모두 생략했다. 큐브맵 반사 조건은 양쪽 모두 64² 프로브 6면을 매 프레임 캡처하며, 깊이 패스만 43→7면으로 줄었다. 반사 내부에서 깊이맵을 중복 생성하지 않는다.

### 반복 간 변동

일부 조건은 반복별 시간 변화가 컸다. 3,000개·포인트 4 국소 이동의 반복별 속도비는 **1.071 / 1.505 / 0.781 / 0.767**이다. 합산 중앙값의 약 1% 개선을 안정적인 이득이라고 주장하지 않는다. 3,000개·포인트 8도 **1.335 / 0.871 / 1.099 / 1.633**으로 변동했다.

혼합 8광원·3,000개 조건은 네 반복 모두 **1.054~1.251배**, 광원 밖 이동은 **1.207~1.353배**였다. 광원별 깊이 면 감소는 모든 측정 프레임에서 정확히 검증했지만, 전체 프레임 시간의 개선율은 배치·광원 겹침·메인 뷰 비용·실행 환경에 따라 달라진다. 측정 변동 원인을 특정할 증거는 수집하지 않았다.

## 구현과 보존 조건

1. 기존 `SceneSpatialCache`에서 얻은 월드 행렬·현재 AABB를 재사용한다. `ShadowInvalidation`은 caster별 ID, 이전 AABB, 실제 깊이에 영향을 주는 데이터 범위와 약한 텍스처 소유권을 보존한다. 원본 GameObject 포인터를 보관하지 않아 삭제 후에도 이전 경계를 안전하게 쓸 수 있다.
2. 월드 행렬·localScale·형상 revision·경계·알파·UV·마스크 텍스처·컴포넌트 자격 변화를 정확 비교한다. 추가는 현재 경계, 삭제/비활성/cast 해제는 이전 경계, 이동은 이전과 현재의 **별도 두 경계**를 사용한다. 순간이동한 중간 공간의 광원까지 불필요하게 무효화하지 않는다.
3. 기존 `SpatialBVH` 구현으로 변경 경계 집합의 BVH를 한 번 구축한다. 포인트 광원의 깊이 6면을 덮는 큐브와 교차 검사하고 첫 교차에서 탐색을 끝낸다. 반경 구로 좁히지 않아 깊이 패스 모서리와 PCF 의존성을 보수적으로 포함한다. 비유한/뒤집힌 경계는 전체 무효화로 처리한다.
4. 광원 슬롯별 단조 증가 revision을 `ShadowMaps`에 전달한다. 광원 이동/범위/종류/레이어 재배치/장면/해상도 변경과 방향광 투영 변경은 기존 갱신 조건도 유지한다. 캐시 정책 전환도 한 번 전체 갱신해 revision 우연 일치로 갱신을 놓치지 않는다.
5. 어떤 깊이맵도 바뀌지 않은 원거리 caster 이동도 반사 버전을 갱신한다. 기존에 동결된 작은 반사 프로브에 과거 기하가 남는 것을 방지한다.

3,000개 국소 이동에서는 선택 모드가 변경 caster **300개**, 이전/현재 경계 **600개**, 변경 BVH **1회**를 기록했다. 정적은 변경 0개·BVH 구축 0회다. `GetShadowInvalidationStats()`의 영향 광원 수는 caster 변화에 의한 무효화만 세며 광원 자체 변경은 별도다. 전역 비교 모드는 개별 차이 계산과 변경 BVH를 생략해 `changed_casters/changed_bounds/dirty_bvh_builds`의 0은 ‘미계측’을 뜻한다.

## 측정 방법

- NVIDIA GeForce RTX 4060 Ti, OpenGL 3.3 / NVIDIA 610.88. CPU 식별 문자열: `AMD64 Family 25 Model 97 Stepping 2, AuthenticAMD`.
- 메인 640×360, 깊이 면 512×512, 기본 바닥 활성. 물체 100/1,000/3,000개, 80% 큐브 + 20% 사각형. 광원 간격 52, 포인트 범위 20·높이 12, 각 물체 군집 16×16이다. 혼합 8광원은 방향 1 + 포인트 7이다.
- 국소 이동은 첫 10% 물체가 한 광원 군집에서 이동한다. 분산 이동은 매 열 번째 물체를 모든 군집에서 움직인다. 정적·모든 광원 겹침·광원 밖 이동·방향광 단독·반사도 포함한다.
- **동일 실행 파일의 전역 무효화 방식과 선택 무효화 방식**을 비교한다. 둘 다 새 공통 스냅샷 수집(경계/기록 메타데이터 및 알파/0스케일 자격 필터)을 사용하므로 과거 바이너리와 바이트 단위로 같은 구현은 아니다. 전역 모드는 전체 데이터 비교만 하고 개별 caster 차이·변경 BVH를 생략한다. 선택 추적과 변경 BVH의 비용은 선택 모드 측정에 포함된다.
- 모드별 독립 Scene/SceneRenderer/ViewportTarget을 유지해 캐시를 서로 채워 주지 않는다. 준비 3프레임 뒤 25프레임 × 4회, 모드당 100개 표본이다. 반복마다 전역/선택 순서를 교대하며 같은 모션 프레임을 재생한다. 총 16조건·3,200개 반복 측정 프레임이다.
- 매 표본 앞뒤에 `glFinish`를 사용한다. CPU 구간은 모션·뷰포트·캐시/BVH·렌더 제출, 완료 구간은 GPU 완료 대기까지 포함한다. `GL_TIME_ELAPSED`는 Render만 감싸고 명령 공급 대기도 포함하므로 순수 GPU 병목 지표로 보지 않는다. p50/p95는 nearest-rank이며 원본에 세 지표 모두 기록한다.
- 각 모드 첫 Render는 `cold` 행 32개로 별도 저장하고 반복 통계에서 제외했다. 장면/렌더러 생성자는 포함하지 않는다. 이미지 readback도 시간 측정에서 제외한다. 빌드·테스트는 벤치마크와 병행하지 않았다.

이전 [5모드 섀도맵 실험](shadow-performance.md)은 다른 배치·카메라·광원 범위를 사용한다. 두 문서의 절대 시간을 직접 전후 비교하면 안 된다.

## 이미지와 회귀 검증

- 벤치마크는 전역/선택/강제 전체 재생성 렌더러를 독립적으로 유지하고 프레임 **1, 2, 7, 19, 0, 23**을 순서대로 진행했다. 캐시된 두 모드와 강제 전체 렌더 간 **192건 모두 최대 채널 오차 0**으로 완전히 일치했다. 캐시를 매번 참조 결과로 미리 채우는 검증이 아니다.
- 별도 `ShadowInvalidation` 회귀 테스트의 **152개 이미지 비교**는 채널 오차 1 이하 조건을 통과했다. 순간이동 출발/도착과 중간 광원 제외, 범위 진입/이탈, 추가/삭제/비활성/컴포넌트 제거, 알파·UV·텍스처·동일 AABB 형상 변경, 부모 이동, 깊이 큐브 모서리, 방향광 범위 맞춤, 광원/해상도/장면 교체, 동결 반사 프로브를 검증한다.
- CPU 검증은 NaN/뒤집힌 이전·현재 경계의 전체 갱신 대체 처리와 정책 전환 시 revision 증가·재안정화를 검사한다. 기존 `ShadowRender`도 통과했다.
- 최종 Release 전체 빌드(에디터·플레이어 포함)가 성공했고 전체 **47개 CTest가 통과**했다. 원시 3,200개 측정 프레임에서 요약의 p50/p95와 카운터 평균을 독립 재계산해 일치함을 확인했다.

## 원본과 재현

위 분석과 측정 요약은 보존하고, 원시 CSV·이미지·환경 기록은 발표 폴더 정리 과정에서 제거했다. `Tests/Benchmarks/ShadowInvalidationBenchmark.cpp`를 실행하면 `summary.csv`, `frames.csv`, `parity.csv`, `metadata.txt`를 다시 만들 수 있다. 새 결과는 개발용 `Engine/Cache/benchmarks/shadows/selective`에 저장한다.

```powershell
cmake --build Engine/Cache/local --config Release --target RiceShadowInvalidationTests RiceShadowInvalidationBenchmark --parallel 4
ctest --test-dir Engine/Cache/local -C Release -R "ShadowInvalidation|ShadowRender" --output-on-failure
./Engine/Cache/local/bin/Release/RiceShadowInvalidationBenchmark.exe Engine/Cache/benchmarks/shadows/selective 25 4
```

출력 디렉터리 뒤 인자는 프레임 수·반복 수·선택적 조건명 부분 문자열이다. 예를 들어 마지막에 `3000_point8`을 추가하면 해당 국소/분산 이동 조건만 실행한다. 실행 시간을 CTest 합격 기준으로 삼지 않는다. 기존 `RiceShadowBenchmark`는 과거 5모드 실험의 의미를 보존하도록 선택 무효화를 명시적으로 끈다.
