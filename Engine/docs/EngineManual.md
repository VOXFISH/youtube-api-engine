# Rice 엔진 사용 설명서

## 범위

Windows x64 / C++20 / OpenGL 3.3 기반의 작은 2D·3D 게임 제작용 엔진이다. 객체 기반 ECS 구성과 공통 속성 등록을 사용한다. 편집기와 독립 플레이어를 제공하며 FMOD Core SDK로 오디오를 처리한다. YouTube·DB·방송 애플리케이션은 포함하지 않는다.

이번 버전은 제작 흐름의 기본 구현이다. 범용 상용 엔진과 동등한 물리·에디터·플랫폼 지원을 의미하지 않는다. 아래 제한을 확인한다.

## 바로 실행

- **Rice.exe**에서 **File → New Project**를 누르고 이름을 입력하면 `Projects/<이름>/<이름>.rice`가 생성된다. 기존 프로젝트는 **File → Open Project**에서 `.rice` 파일을 선택한다.
- **RicePlayer.exe**는 로컬 게임용이다. 실행 후 `Builds`에서 게임 EXE를 고르거나 게임 EXE를 RicePlayer 위에 끌어 놓는다. 완성된 게임 EXE는 자체적으로 실행할 수도 있다.
- **RiceCon.exe**는 빌드를 등록하고 YouTube 송출을 운영하는 별도 앱이다. 빌드 파일을 RiceCon 위에 끌어 놓거나 `RiceCon.exe --build <게임.exe>`로 등록한다.
- 예제 프로젝트는 `Projects/Grass1000/Grass1000.rice`와 `Projects/Steve/Steve.rice`에서 연다. **Game → Play**로 실행한다.
- 명령줄에서는 `Rice.exe <이름.rice>`, `Rice.exe --new-project <새 프로젝트 폴더>`, `Rice.exe --project <이름.rice> --export <새 게임.exe>`를 사용할 수 있다.

## 함수 실행 시간 측정

편집기에서 **Window → Benchmark**를 연다. 상단 도구 모음의 **Play** 전에는 프레임 번호가 0이며, Play 다음 전체 프레임부터 1로 시작한다. Stop하면 다시 0이 된다. `Start`에 프레임 번호를 입력하고 **Schedule**을 누르면 예약한다. Play 전에 1번 프레임부터 예약할 수도 있다. 씬이 실행 중일 때 **Benchmark** 창의 **Play**는 클릭한 프레임을 `Start`로 지정해 즉시 측정을 시작한다. `Frames`는 수집할 프레임 개수이고 `Intervals`는 샘플 사이의 프레임 간격이다. 예를 들어 100, 3, 2를 지정하면 100·102·104번 프레임을 수집한다. Stop은 진행 중인 측정을 취소하고 완료된 결과는 유지한다.

**Time**은 실제 호출의 시작 시각과 경과 시간을 보여 준다. **Rate**는 자식 호출 시간을 제외한 함수 자체 시간을 합산해 점유율이 큰 순서로 보여 준다. 함수·스크립트 파일·기능 폴더 단위로 전환할 수 있다. 그래프에서 휠을 굴리거나 가운데 버튼을 누른 채 위아래로 드래그하면 확대·축소된다. 구간을 클릭하면 커서 옆에 호출 로그가 나타난다. 회색 `misc.`에서는 커서를 그대로 두고 휠로 개별 호출을 읽을 수 있다.

스레드 제목의 화살표를 누르면 그 스레드의 중첩 호출 줄을 접거나 펼친다. 접은 상태에서도 구간을 클릭하면 자식 호출 로그를 읽을 수 있다. 계측된 작업 스레드는 각각 별도 제목과 같은 시간축으로 표시된다. Rate의 비율은 표시된 모든 스레드의 함수 자체 시간 합을 기준으로 한다.

함수 로그는 예약된 진단 프레임에서만 켜진다. 편집 중, Start 이전, 샘플 사이의 간격, 진단 완료 후에는 함수 호출을 수집하지 않는다. Benchmark 창의 **Play**로 현재 프레임에서 시작하면 클릭 이후 호출만 기록한다. 첫 프레임 전체를 측정하려면 미래 Start를 예약한다.

별도 기록 스레드는 먼저 실행 파일 옆의 `Logs/functions.bin`에 바이너리를 저장한다. 진단이 끝나면 같은 스레드가 이를 `Logs/functions.tsv`로 변환하며, 창에 **Exporting log...**가 표시된다. 다음 진단은 `functions.capture-2.bin`/`.tsv`처럼 별도 파일을 사용하고, 이전 실행의 같은 이름 파일은 보관 이름으로 옮긴다. **Log ready**에 마우스를 올리면 해당 진단의 실제 경로를 확인할 수 있다. TSV에는 프레임 번호, 시간(ns), 중첩 깊이, 파일, 줄 번호, 함수명, 스레드 ID·이름 및 호출 ID가 들어간다. 일반 Console 메시지는 함수 계측과 별도로 계속 표시된다. 새 C++ 스크립트의 콜백이나 보조 함수도 개별적으로 보려면 `Rice/Benchmark.h`를 포함하고 함수 본문 첫 줄에 `RICE_BENCHMARK_FUNCTION();`을 추가한다. 작업 스레드 안에서 `Benchmark::SetThreadName("Physics");`처럼 이름을 붙일 수 있다.

Hierarchy는 오브젝트 생성·삭제, 부모·그룹 변경, 순서 변경 및 풀링 상태 변경 시에만 트리를 갱신한다. 접기·펼치기와 선택 변경은 표시 목록만 갱신하며 화면 밖의 행은 그리지 않는다.

## 빌드

Visual Studio C++ 도구, Windows SDK, CMake 3.25 이상(VS 2026 생성기는 이를 지원하는 최신 CMake), vcpkg, FMOD Studio API Windows의 Core SDK가 필요하다. FMOD Studio 편집기만 설치된 것으로는 부족하다.

```powershell
$env:VCPKG_ROOT = 'C:/path/to/vcpkg'
./Engine/Build.ps1 -FmodRoot 'C:/Program Files (x86)/FMOD SoundSystem/FMOD Studio API Windows'
```

`Engine/Build.cmd`도 같은 스크립트를 실행한다. 빌드와 CTest를 마치면 설치 루트의 세 실행 파일과 `Engine/Runtime`을 갱신한다. 중간 산출물은 `Engine/Cache/local`에 둔다. 기존 의존성은 `-InstalledDependencies <vcpkg_installed 절대 경로>`로 지정할 수 있다.

FMOD 경로는 CMake의 FMOD_ROOT 캐시 값으로도 지정한다. x64 fmod_vc.lib, fmod.dll, fmod.hpp를 확인하며 SDK가 없으면 구성 단계에서 실패한다. SDK 소스·바이너리는 저장소에 추가하지 않는다. 실제 배포에는 사용 중인 FMOD 라이선스 조건을 적용해야 한다.

## 편집 흐름

Hierarchy에서 객체를 선택하고 Inspector에서 속성을 조절한다. 모든 편집은 메모리에 반영되고 Save로 저장한다.

### Custom Shape 편집

MeshRenderer의 **Shape → Custom**을 선택하고 **Open Shape Editor**를 누른다. 처음 Custom으로 전환하면 현재 기본 도형의 정점과 삼각형을 복사한다. Create object → Basic shapes → Custom으로도 만들 수 있으며, 이때 시작 도형은 Cube다. 편집한 Custom을 다른 기본 도형으로 바꿨다가 다시 Custom으로 선택하면 기존 편집 내용을 사용한다.

Shape Editor는 열 때 지정한 오브젝트의 메시만 로컬 좌표로 표시한다. 다른 오브젝트를 선택해도 편집 대상은 바뀌지 않는다. 처음에는 조명 없이 표시한다. 상단 **View** 옆의 **Lighting preview**를 체크하면 씬의 광원으로 메시를 비춰 FBX 코너 법선이 만드는 곡면 음영을 확인할 수 있다. 활성 광원이 없는 씬에서는 미리보기용 방향광을 사용한다. 체크를 해제하면 원래 표시로 돌아간다. 휠로 확대·축소하고 가운데 버튼 드래그로 회전한다. 가운데 버튼 클릭 또는 Camera 체크로 카메라 이동 모드를 전환한다. Camera 모드에서는 WASD·Q/E로 이동하고 좌드래그로 패닝, 우드래그로 시선을 회전한다. **Frame shape**는 도형 전체가 보이도록 카메라를 맞춘다.

상단에는 **File / Edit / View** 메뉴와 **Save / Load / General / Triangles / Frame shape / Camera** 툴바가 있다. Shape Editor는 씬과 분리된 편집 사본을 사용하며 **Save → in scene**을 실행할 때 씬에 반영한다. `.riceshape`에는 정점·삼각형 인덱스·UV, FBX에서 가져온 코너 법선과 면 그룹, Pivot, Anchor의 위치·회전·크기 및 표시 설정이 저장된다. 씬의 child 연결은 애셋에 저장하지 않는다. 현재 파일명 옆의 `*`는 마지막 파일 저장 이후 변경된 내용이 있음을 표시한다.

| Save 항목 | 동작 | Shape Editor 단축키 |
|---|---|---|
| **in scene** | 프로젝트 `Assets/Shapes`에 새 애셋을 만들고 현재 씬 오브젝트에 적용한다. 이름은 `기존이름_scene.riceshape`, 이후에는 `기존이름_scene_1.riceshape`, `_2`, …이며 기존 파일을 덮어쓰지 않는다. | Ctrl+Shift+O |
| **as asset** | 현재 연결된 파일 위치에 덮어쓴다. 현재 씬 오브젝트와 씬에 저장된 도형은 바뀌지 않는다. 연결된 파일이 없으면 먼저 elsewhere로 저장한다. | Ctrl+Shift+S |
| **elsewhere...** | Windows 파일 선택 창에서 지정한 경로에 저장하고 그 파일을 현재 애셋으로 사용한다. 씬에는 적용하지 않는다. | — |

이 단축키는 Shape Editor 또는 그 내부 패널에 포커스가 있을 때만 동작한다. in scene으로 반영한 내용은 메인 편집기 Undo로 되돌릴 수 있고 생성된 애셋 파일은 유지된다. 현재 씬 전체를 디스크에 기록하려면 메인 편집기의 Save를 사용한다.

**Load** / **File → Load...** / Ctrl+O로 `.riceshape` 파일을 선택하면 편집 사본에 도형과 General 속성을 적용하고 화면을 맞춘다. 씬의 오브젝트는 유지한다. 불러오기는 Shape Editor의 Undo/Redo로 되돌릴 수 있으며, 선택 취소나 잘못된 파일은 기존 편집 내용을 유지한다. 저장·불러오기 오류는 툴바 아래에 표시한다.

**Vertex list**는 처음에 숨겨져 있다. 상단 **Edit → Vertex list**로 열고 패널 오른쪽 위 **X**로 닫는다. 패널을 닫으면 View가 넓어지고 정점 선택과 편집 내용은 유지된다. Edit 메뉴에는 Undo/Redo도 있으며, View 메뉴에서 Frame shape와 Camera를 사용할 수 있다.

상단 **Lighting preview** 옆의 **Show markers**는 기본으로 켜져 있다. 체크를 해제하면 뷰포트에서 정점과 삼각형을 나타내는 표시가 함께 사라져 곡면 음영을 살펴볼 수 있다. 다시 체크하면 같은 위치에 표시된다.

**Triangles** 버튼이나 **Edit → Triangles**로 면 그룹 목록을 연다. FBX에 지정된 그룹을 사용하고, 그룹 정보가 없는 삼각형은 모서리를 공유하며 같은 평면에 놓인 것끼리 묶는다. 그룹 왼쪽 화살표를 누르면 소속 삼각형을 펼치거나 접는다. 그룹 이름을 누르면 그룹의 모든 정점이 선택된다.

목록에서 삼각형을 누르면 같은 그룹의 면과 정점이 연한 분홍색으로 표시되고, 목록 아래에서 해당 삼각형의 재질을 편집할 수 있다. 미리보기에서 흰 삼각형 표시를 눌러도 같은 동작을 하며, 해당 그룹이 펼쳐지고 **Vertex list**도 열린다. 미리보기의 삼각형 표시는 면의 중심에서 화면상 크기의 **20%**로 그리며, 긴 쪽이 **5px 이하**이거나 다른 면에 가려지면 숨긴다. 가려진 삼각형도 목록에서 선택할 수 있다.

그룹 이름을 누르면 그룹 전체의 **Enabled / Metalicity / Roughness / Albedo · Cubemap**을 편집할 수 있다. 값이 서로 다른 속성은 혼합 상태로 표시되며, 편집한 속성만 소속 삼각형 전체에 적용된다. 삼각형 행을 누르면 해당 삼각형 하나의 속성을 편집한다.

그룹 재질에서 **Link textures**를 체크하면 텍스처 한 장이 그룹 전체에 이어진다. 체크를 해제하면 같은 텍스처가 각 삼각형에 반복된다. 체크를 바꾸면 현재 텍스처의 배치를 미리보기에서 바로 확인할 수 있다. UV 배치는 `.riceshape`에도 저장된다. 금속성과 거칠기가 직접광에 미치는 효과는 **Lighting preview**를 켜거나 Scene/Game 뷰에서 확인한다. 재질과 UV 편집은 Shape Editor의 Undo/Redo를 지원한다.

면별 설정은 **Save → in scene**으로 현재 오브젝트에 적용한다. Inspector와 해당 **Material** 제목에는 **(edited in shape editor)**가 붙는다. Inspector에서 Material을 변경하면 **"all edits from the shape editor will be overwritten!"** 경고가 해당 영역을 덮는다. **Return**은 변경을 취소하고 면별 설정을 유지한다. **Proceed**는 제안한 Material·Texture 설정을 모든 삼각형에 적용하고 edited 표시를 없앤다. 열려 있는 Shape Editor의 면별 설정도 함께 초기화하며 정점 편집 내용은 유지한다. 이 적용은 메인 편집기 Undo로 되돌릴 수 있다.

면별 설정과 edited 상태는 **오브젝트별 씬 데이터**에 저장되어 Game, 씬 재로드, 복제, Prefab 인스턴스와 Export에서 유지된다. 다른 오브젝트나 공유 Texture 애셋은 변경하지 않는다. `.riceshape` 파일에는 이 오브젝트별 설정을 기록하지 않으므로 **as asset / elsewhere** 이후에도 아직 씬에 반영하지 않은 면별 설정은 `*` 상태로 남는다. 면별 설정까지 남기려면 **in scene**을 사용한 다음 메인 편집기의 **Save**로 씬을 저장한다.

**General**은 툴바의 General 버튼 또는 **Edit → General**로 열고 닫으며 패널 오른쪽 위 **X**로도 닫을 수 있다. **Pivot (X / Y / Z)**은 도형의 로컬 경계에 대한 비율이다. 0은 좌·하·후면 끝, 1은 우·상·전면 끝, 기본값 0.5는 중심이다. 음수나 1보다 큰 값도 입력할 수 있다. Pivot이 Shape Editor의 원점이며 Vertex list 좌표도 이 원점을 기준으로 표시한다. 씬에서는 **Inspector → Transform → Pivot**으로 직접 편집할 수 있고, 회전과 크기 변경의 기준점으로 사용한다.

**Anchor**는 General의 **Add Anchor** 또는 Inspector의 컴포넌트 추가에서 붙인다. **Child** 목록에서 해당 오브젝트의 직접 자식을 선택하면 자식 Pivot이 부모 Anchor에 붙는다. 연결하지 않으면 `none`이다. **Translation / Rotation / Scale**은 부모 Pivot을 기준으로 Anchor의 위치와 자식이 물려받을 방향·크기를 정한다. 연결 중인 자식의 로컬 Translation은 Pivot을 Anchor에서 분리하지 않는다. **Enabled**를 끄면 연결 제약을 해제한다.

씬 View에서 부모 오브젝트를 선택하면 Anchor가 노란 점과 방향 화살표로 표시된다. Shape Editor에서는 **On in Shape Editor**가 켜져 있으면 노란 화살표가 달린 RGB 큐브로 표시된다. 이 표시만 꺼도 자식 연결은 유지된다. 큐브 면 좌드래그로 Anchor를 이동하고 우드래그로 방향을 회전한다. General에서 바꾼 Pivot·Anchor와 child 연결은 **Save → in scene**으로 씬에 적용한다.

- 정점은 반지름 2픽셀 흰 원이며, 마우스가 10픽셀 안에 오면 반지름 5픽셀로 커진다. 선택된 정점은 노란색이다.
- 정점을 클릭하면 최대 화면 크기 20픽셀의 축 정렬 큐브가 나타난다. 카메라 확대·축소·회전에도 화면 크기를 유지한다. 면 색상은 수직축 기준 X=red, Y=green, Z=blue이고 조명의 영향을 받지 않는다.
- 큐브 면 좌드래그는 면의 수직축을 따라 선택된 정점을 함께 이동한다. 예를 들어 XY 면은 Z축 이동이다. 축이 카메라를 향하면 위아래 드래그로 깊이를 조절한다.
- 큐브 면 우드래그는 클릭한 정점을 중심으로 Shape 전체를 해당 수직축 주위로 회전한다. 오브젝트의 Transform은 유지한다.
- Shift+좌클릭으로 정점을 추가한다. Ctrl+드래그는 점선 사각형 안의 보이는 정점만 선택하고, Ctrl+Shift+드래그는 기존 선택에 추가한다. 노란 정점을 클릭하면 다중 선택을 유지하고, 다른 흰 정점을 클릭하면 이전 선택을 해제한다.
- **Vertex list**는 창을 열 때 인덱스 버퍼에서 처음 등장하는 순서로 `vertex 0`, `vertex 1`, …을 부여한다. UV 경계나 면 경계에서 같은 위치인 정점은 연결된 하나의 정점으로 편집한다. 번호 클릭 또는 XYZ 좌표 편집 시 해당 정점에 큐브가 나타난다. 목록의 Shift+클릭 및 Shift+위/아래 방향키는 범위를 선택한다. 마지막으로 클릭하거나 좌표를 편집한 정점이 회전 중심이며, Shift+방향키는 회전 중심을 바꾸지 않는다. 목록에서는 가려진 정점도 직접 선택할 수 있다.
- 드래그 및 좌표 편집은 각각 한 번의 Undo/Redo로 되돌릴 수 있다. Esc는 진행 중인 정점·Anchor 드래그를 취소한다. **Save → in scene**으로 적용한 변경은 Scene/Game 화면, 씬 저장, 복제, 클립보드, Prefab 및 독립 플레이어에서 유지된다. 편집 대상 삭제, 씬 전환, Play 시작 시 창을 닫는다. 씬에 적용하거나 애셋으로 저장하지 않은 편집 사본은 창을 닫으면 버려진다.

1. Create object로 생성한다. Name, Active, Parent 및 로컬 위치·회전·크기, 월드 위치를 편집한다.
2. Add 항목으로 컴포넌트를 붙인다. 타입당 하나이며 Transform은 필수다.
3. Duplicate는 선택 객체의 속성·컴포넌트와 부모 참조를 복제한다. 자식 하위 트리 전체를 복제하지 않는다.
4. Delete는 객체와 자손을 삭제한다. Remove component는 해당 컴포넌트를 제거한다.
5. Undo/Redo는 장면 편집을 최대 100개 되돌린다. 에셋 파일 관리·프로젝트 전환·입력 매핑은 이 기록에 포함하지 않는다.
6. Play는 편집 씬을 복제해 실행한다. Stop은 플레이 직전 씬으로 복원한다. 플레이 중 변경한 값은 저장하지 않는다.
7. **File** 메뉴에서 프로젝트를 만들거나 연다. 독립 게임은 **Project / Export → Build standalone game**으로 내보낸다.

Parent 변경은 로컬 Transform 값을 유지하므로 월드 위치가 바뀔 수 있다. 순환 부모 관계와 다른 씬의 부모는 거부한다. 월드 회전·크기는 GetWorldMatrix로 조회할 수 있다. 부모의 크기가 0이면 월드 이동 역변환을 할 수 없으므로 오류를 표시한다.

## 여러 씬과 Prefab

**Hierarchy → Scene**에서 프로젝트에 저장된 씬을 선택한다. 전환할 때 현재 씬을 자동 저장하고, 선택한 씬은 다음 실행과 Export에도 유지된다. **New Scene**은 빈 씬을 만들고 **Duplicate Scene**은 현재 씬을 복사한다. 씬 생성·전환은 Stop 상태에서 수행한다.

객체를 선택하고 **Hierarchy → Save as Prefab**을 누르면 자식·그룹 구성, 등록된 컴포넌트와 속성을 `Prefabs/<이름>.prefab`에 저장한다. **Project → Prefabs**에서 Prefab과 생성 위치를 선택한 뒤 **Instantiate**로 배치한다. 편집 중에는 일반 씬 객체로 저장되며 Undo할 수 있다.

Play 중 Instantiate는 풀에서 객체를 재사용하고 부족하면 추가한다. **Prewarm**으로 미리 준비할 수 있고, 생성한 루트 객체를 선택한 뒤 **Release selected to pool**로 반환한다. 반환된 객체는 비활성화되어 Hierarchy에서 숨겨진다. Stop이나 씬 전환은 런타임 풀을 정리한다.

게임 스크립트에서도 `Start`·`Update` 등 플레이 중 콜백에서 다음 API를 사용한다. `Awake`는 씬 복원 중 Prefab 연결 전에 호출되므로 여기서 생성하지 않는다. `Start`는 컴포넌트 수명 동안 한 번만 호출된다. 재사용할 때마다 초기화할 사용자 상태는 `OnPoolAcquire()`에서, 반환 시 정리할 상태는 `OnPoolRelease()`에서 처리한다. 등록된 속성은 재사용 시 Prefab 저장값으로 복원된다.

```cpp
auto& scene = GetGameObject().GetScene();
scene.PrewarmPrefab("Enemy", 10);
auto& enemy = scene.InstantiatePrefab("Enemy", {3, 0, 2});
scene.ReleasePrefab(enemy.GetID());
```

## 컴포넌트

같은 텍스처·재질을 사용하는 연속된 기본 큐브는 자동으로 GPU instancing으로 묶인다. 메시를 공유하고 각 큐브의 월드 행렬·색상을 인스턴스 버퍼로 전달하므로 개별 위치·회전·크기·색상 편집은 그대로 반영된다. Sprite, 사용자 Shape, 면별 재질 편집, 반사 수신 객체는 기존 렌더 경로를 사용한다. 객체의 순서·활성 상태와 씬 저장 형식은 유지된다.

개발용 비교 도구 `Engine/Cache/local/bin/Release/RiceInstancingBenchmark.exe <프로젝트 폴더> <결과 폴더> [측정 프레임=240] [비교 쌍=3] [렌더 패스=1]`는 Grass1000에서 같은 실행 파일의 instancing을 켜고 끄며 정지·이동 카메라와 함수 로깅 유무를 비교한다. 각 실행에서 60프레임을 워밍업하고 CSV와 이미지 비교 결과를 저장한다. CPU Render와 GPU 완료·로그 대기를 포함한 비용을 분리하며, 편집기 UI와 화면 교환은 측정하지 않으므로 에디터 FPS로 해석하지 않는다.

| 컴포넌트 | 기능 / 편집 속성 |
|---|---|
| Transform | 위치, 도 단위 오일러 회전, 크기, Pivot, 부모 계층 |
| Anchor | 직접 자식 연결, 부모 Pivot 기준 위치·회전·크기, Shape Editor 표시 |
| MeshRenderer | 단위 큐브, 색상 |
| SpriteRenderer | 이미지 에셋 ID, 색상, 이미지 선택 |
| Light | Point/Directional, 색상, 세기, 방향, Range; 최대 활성 8개 |
| BoxCollider | 로컬 중심, 크기, Trigger, 겹침 상태 |
| Rigidbody | 속도, 질량, 반발계수, 중력, Kinematic |
| SpriteAnimator | 균일 스프라이트시트 열·행·프레임 수, FPS, Loop, Playing |
| AudioSource | 오디오 에셋 ID, Volume, Loop, Play on start; Play/Pause/Resume/Stop |
| UIText | 텍스트, 화면 픽셀 위치, 색상, 글자 크기 |
| UIButton | 텍스트, 화면 픽셀 위치·크기, 액션 이름 |
| PlayerController | 이동 속도; Left/Right/Forward/Backward/Jump 액션 사용 |
| Spin | 사용자 컴포넌트 등록 예시. 초당 회전 각도 |

SpriteAnimator는 왼쪽 위에서 오른쪽으로, 다음 행 순서로 프레임을 읽는다. SpriteRenderer와 같은 객체에 부착한다. Sprite 이미지는 XY 평면이다. 현재 알파 0.1 미만은 버리는 cutout 방식이며 반투명 정렬·블렌딩은 지원하지 않는다.

UI는 화면 좌상단 기준 픽셀 좌표다. UIText의 `{score}`는 샘플 점수로 치환된다. 기본 버튼 액션은 Increment와 Quit이며 코드에서 Workspace::actions에 추가할 수 있다. 편집 모드에서 버튼은 실행되지 않는다. 기본 폰트에는 한국어 글리프가 없으므로 한국어 게임 UI에는 별도의 ImGui 폰트 등록이 필요하다.

## 물리와 충돌

고정 60Hz로 중력, 선형 속도, AABB 침투 보정·반발을 처리한다. 한 프레임에서 최대 0.1초를 따라잡는다. Collider만 있으면 고정 물체, Rigidbody가 있고 Kinematic이 꺼져 있으면 동적 물체다. Kinematic을 켜면 중력·충돌 반발에 의해 움직이지 않고 지정한 Velocity 또는 스크립트로 이동하며 충돌에 참여한다. Trigger는 이벤트만 발생시키고 물리 반응을 하지 않는다.

컴포넌트의 OnCollisionEnter/Stay/Exit 및 OnTriggerEnter/Stay/Exit에서 상대 EntityID를 받는다. GetGameObject().GetScene().Find(id)로 조회한다. 삭제된 객체는 nullptr일 수 있다. 회전된 상자는 월드 AABB로 감싸므로 실제 표면보다 먼저 충돌할 수 있다. 회전 역학·마찰·관절·연속 충돌 검출은 없다. 빠른 물체는 얇은 물체를 통과할 수 있다. 이 물리는 간단한 게임용이며 정밀 시뮬레이션용이 아니다.

## 에셋과 입력

툴바 또는 Project 패널의 **Import...**에서 `.fbx` 파일을 고른다. 편집 중인 씬에 모델이 추가되며 Hierarchy에서 하위 오브젝트를 선택해 개별 편집할 수 있다. **Save**를 눌러 씬을 저장한다.

FBX의 코너별 법선은 씬과 `.riceshape`에 보존된다. Scene과 Game은 이 법선을 보간해 곡면을 부드럽게 표시하고, 같은 위치에 서로 다른 법선이 지정된 모서리는 날카롭게 표시한다. 법선이 없거나 길이가 0인 코너에는 해당 삼각형에 수직인 면 법선을 사용한다.

이미지·오디오는 같은 대화상자의 **All assets** 필터로 선택한다. 파일은 프로젝트 `Assets`로 복사되며 Inspector에서 연결할 수 있다. **New relative filename**과 **Rename**으로 하위 폴더 이동·이름 변경을 할 수 있으며 애셋 ID는 유지된다.

각 파일의 `.meta`에 128비트 식별자가 저장된다. 파일을 외부에서 옮기면 대응하는 .meta도 함께 옮긴다. Refresh는 목록을 다시 읽는다. 파일 내용의 자동 hot reload는 제공하지 않는다. 이미지와 FMOD 사운드는 공유 캐시로 중복 로딩을 줄인다.

입력은 GLFW 키 코드로 설정한다. 기본 A=65, D=68, W=87, S=83, Space=32다. Add / rebind action으로 액션을 추가하며 Save로 보관한다. 코드에는 Held/Pressed/Released/Axis가 있다. 텍스트 입력 중 게임 이동을 억제한다.

## 저장과 배포

**File → Close Project**는 시작 화면으로 돌아간다. 프로젝트를 닫거나 다른 프로젝트로 바꾸거나 Rice를 종료할 때 미저장 변경이 있으면 **Save**, **Don't Save**, **Go Back**을 선택한다. **Save**는 프로젝트와 열려 있는 편집본을 저장한 뒤 요청한 동작을 계속한다. **Don't Save**는 변경을 버리고 계속하며, **Go Back**은 편집을 계속한다. 저장 오류가 발생하면 선택창에서 오류를 확인하고 프로젝트로 돌아갈 수 있다.

프로젝트 루트의 `<이름>.rice` 한 파일에 입력 매핑, 현재 씬과 다른 모든 씬을 저장한다. 이미지·소리 등 원본은 `Assets`, RiceMonkey 소스는 `Scripts`, 프리팹은 `Prefabs`, 프로젝트 설정은 `Settings`, 작업 파일은 `Temp`에 둔다. 이전 형식의 프로젝트도 열 수 있으며, 새 형식으로 저장하면 이전 프로젝트와 씬 파일의 사본이 `Temp/Legacy`에 남는다.

Project 패널의 **Build file**에 출력할 파일명을 지정하고 **Build standalone game**을 누른다. 기본값은 `Builds/<프로젝트명>.exe`이며, 같은 이름의 빌드가 있으면 다음 번호를 제안한다. 플레이어, DLL, 애셋, 저장된 씬과 배포용 스크립트 모듈이 하나의 Windows 게임 EXE에 포함된다. 이 파일을 다른 폴더나 호환되는 Windows PC로 복사해 직접 실행할 수 있다. 게임은 실행할 때 전용 임시 폴더에 런타임을 풀고 정상 종료 시 정리한다.

## 코드로 확장

Sandbox/Scripts/GameComponents.h의 Spin 예시를 따른다. ComponentRegistry::Register에 속성을 등록하면 같은 정의가 GUI, 저장·복원, 복제, Undo, Play 복제에 사용된다. 등록하지 않은 사용자 컴포넌트가 있으면 저장·플레이를 명시적으로 거부한다. 커스텀 등록은 프로젝트 로딩 전에 실행되어야 하므로 Workspace 생성자의 세 번째 콜백으로 전달한다.

```cpp
struct Health : Rice::MonoBehaviour {
    float hp = 100;
    void OnTriggerEnter(Rice::EntityID other) override { hp -= 10; }
};
// RegisterGameComponents 함수 안:
registry.Register<Health>("Health", [](Health& c, const Rice::PropertyVisitor& f) {
    f("HP", &c.hp);
});
// 코드로 부착:
auto& object = workspace.editor.scene->CreateGameObject("Character");
object.AddComponent<Health>();
object.AddComponent<Rice::BoxCollider>();
```

임의 std::function 콜백 자체는 직렬화하지 않는다. 게임 버튼 동작은 Workspace::actions에 등록하거나 커스텀 컴포넌트 Start에서 연결한다. 런타임 C++ 컴파일·핫 리로드는 제공하지 않는다.

## 검증과 제한

CTest는 생명 주기, Transform·계층·삭제, 전체 내장 컴포넌트 저장·복원, 잘못된 씬 거부, 복제, Undo/Redo, Play/Stop 복원, 물리 착지·Trigger 전이, 애니메이션, 에셋 이름 변경·경로 제한, FMOD 채널 재생·정지를 확인한다. 편집기와 배포 플레이어의 120프레임 실행 및 다른 작업 디렉터리에서의 실행도 확인한다.

GUI 화면을 확인하고 겹친 패널의 초기 배치를 수정했다. 사용자가 Esc로 컴퓨터 조작을 중단하여 개별 컨트롤의 수동 상호작용 검증은 완료하지 않았다. 다른 PC·GPU에서의 실행과 장시간 안정성은 미검증이다.

진단 창은 FPS, 업데이트 CPU 시간, 객체 수, 최근 200개 로그를 표시한다. 성능 캡처, GPU 프로파일러, 크래시 덤프 수집은 포함하지 않는다. 현재 단일 시작 씬, 단일 스레드, 점광원/방향광·큐브 중심 3D, 객체 기반 컴포넌트 저장소를 사용한다. 고급 모델·애니메이션·그림자·네트워크·외부 데이터 저장은 범위 밖이다.


## 도킹 편집기 레이아웃

하나의 네이티브 창 안에 전체 도킹 영역을 둔다. 기본 배치는 왼쪽 Hierarchy, 가운데 Scene/Game 탭, 오른쪽 Inspector, 아래 Project/Console/Input 탭이다. 상단 도구 모음에는 Play/Stop, Save, Undo/Redo와 Window 메뉴가 있다.

- 패널 탭이나 제목 표시줄을 드래그해 도킹 표시가 나타난 영역에 놓으면 좌우·상하로 분할하거나 탭으로 합칠 수 있다.
- 패널 경계선을 드래그하면 크기가 바뀐다. Scene/Game 렌더 타깃과 카메라 종횡비가 패널 크기에 맞춰 갱신된다.
- X로 닫은 패널은 Window 메뉴에서 다시 연다.
- Window → Save layout은 현재 배치를 저장한다. 일반 종료 때도 배치를 저장한다. 저장 위치는 편집기 실행 파일 옆 EditorLayout.ini다.
- Window → Reset layout은 기본 배치와 전체 패널을 복원한다. 닫힘 여부는 다음 실행까지 유지하지 않으며, 재시작하면 패널을 다시 연다.
- Game은 게임 카메라의 화면과 HUD/버튼을 포함하고, Scene은 같은 씬을 독립적인 편집 카메라로 보여준다.
- 플레이 중 Game 패널을 클릭해 포커스를 준 뒤 게임 입력을 사용한다. 다른 패널을 편집하거나 텍스트를 입력하는 동안 이동 입력을 차단한다.

Scene/Game은 OpenGL framebuffer의 컬러 텍스처를 패널에 표시한다. 독립 RicePlayer는 전체 창 렌더링을 사용한다. 패널은 별도 OS 창으로 분리되지 않는다.

도킹 버전 확인: Release 빌드·기존 자동 테스트·120프레임 실행·EditorLayout.ini 도킹 노드 저장이 통과했다. 실제 GUI에서 기본 배치 및 Scene/Game 탭 전환과 HUD 표시를 확인했다. 사용자가 Esc로 컴퓨터 조작을 중단하여 드래그 재도킹·Play 버튼의 수동 검증은 완료하지 못했다.


## 통합 Console 로그

엔진의 RICE_CORE_* 로그, 게임의 RICE_LOG/RICE_ERROR 등 로그, 기본 spdlog 로그와 Workspace 메시지가 하나의 Console 패널에 표시된다. 창 생성·OpenGL 장치 정보처럼 패널 생성 이전의 로그도 보관한다. 시간, 로그 수준, Rice/APP 출처를 표시하며 경고는 노란색, 오류는 빨간색이다. Auto-scroll을 끄면 과거 로그를 읽을 수 있고 Clear log는 표시 버퍼를 비운다.

메모리 버퍼는 최근 2,000건, 개별 메시지는 약 16 KiB까지 보관한다. 여러 스레드에서 로그를 남겨도 UI는 안전한 스냅샷을 읽는다. 로그 파일을 자동 생성하지 않는다. 직접 printf/std::cout 또는 외부 프로세스의 출력은 캡처하지 않으므로 게임 코드는 엔진 로그 API를 사용한다.

편집기와 플레이어는 Windows GUI 서브시스템 실행 파일이므로 별도 터미널 창이 생성되지 않는다. UI가 열리기 전의 치명적 오류는 오류 대화상자로 알리며 --smoke 실행에서는 종료 코드로만 보고한다. 독립 플레이어는 편집기 Console 패널을 표시하지 않는다.


## Scene Transform 핸들

Scene 탭에서 객체를 좌클릭하거나 Hierarchy에서 선택하면 로컬 경계를 따라 투명한 와이어 박스와 핸들이 표시된다. 화면에서 가장 가까운 객체의 박스 경계를 기준으로 선택한다. Sprite는 이미지 사각형 경계로 선택하며 투명 픽셀까지 구분하지 않는다. 빈 공간 클릭은 선택을 해제한다. Game 뷰와 Play 모드에는 편집 핸들이 없다.

- 꼭짓점의 사각형 8개: 반대쪽 꼭짓점을 고정하고 잡은 꼭짓점 쪽으로 세 축의 크기를 함께 조절한다.
- 모서리 중앙의 사각형 12개: 반대쪽 모서리를 고정하고 잡은 모서리에 수직인 평면에서 두 축의 크기를 독립적으로 조절한다. 마우스 광선과 해당 평면의 교차점을 사용하므로 한 축만 변경하거나 한 축은 늘리고 다른 축은 줄일 수 있다. 크기는 드래그 시작 크기의 최소 2%까지 제한하여 0을 지나 뒤집히지 않게 한다.
- 면 중심 원 6개: 빨강 X, 초록 Y, 파랑 Z다. 좌클릭 드래그는 해당 면의 평면 안에서만 이동한다. 마우스 광선과 드래그 시작 시 고정한 월드 평면의 교차점을 사용한다. 면이 카메라와 거의 평행해 교차점을 구할 수 없으면 이동을 보류한다.
- 원 우클릭을 누른 채 바깥으로 끌어 기준 방향을 잡은 뒤 원 주위로 마우스를 원형으로 움직이면 회전한다. 선택한 원과 반대 면 중심 원을 잇는 선이 회전축이다. 물체 중심과 축 위 두 원은 고정되며 화면에서 시계/반시계로 움직인 방향을 따라 회전한다. 원 중심에서 12픽셀 안쪽은 방향이 불안정하므로 각도를 누적하지 않는다.
- 90도의 배수 주변 ±5도 구간에서 고정된다. 예: 85~95도는 90도로 표시되고 95도를 초과하면 실제 값으로 돌아온다. 같은 드래그에서 역방향으로 접근할 때는 92도 등의 값을 자유롭게 맞출 수 있으며 중심을 통과하면 보정을 다시 활성화한다. 음수·180도·360도에도 적용된다. Inspector 숫자 입력에는 이 보정을 강제하지 않는다.
- 드래그를 놓으면 Undo 한 단계로 기록한다. Esc, 뷰 포커스 상실, 뷰 닫기/숨김은 진행 중인 드래그를 취소한다. 선택된 객체 참조는 ID로 재조회한다.

우클릭 회전은 두 면 중심을 잇는 월드 축 회전 행렬을 적용한 후 부모 공간으로 환산하고 연속적인 Euler 표현으로 Inspector에 반영한다. 여러 축이 이미 회전한 경우 Euler 성분들이 함께 변할 수 있으며, 스냅의 기준은 드래그 시작 시 선택 축의 Euler 값에 누적한 회전량이다. 부모의 변환도 선택·위치·피벗 계산에 반영한다. 크기가 0인 특이 변환에서는 핸들을 비활성화하며 Inspector에서 크기를 복구할 수 있다.

`--gizmo-smoke --silent-audio`는 편집 모드에서 첫 객체를 선택하고 120프레임 핸들 표시 경로를 실행한다. Gizmo 자동 테스트는 회전 보정·역방향 미세 조정, 투영·선택, 면 피벗 보존, 크기 변경, Undo/Redo를 검사한다.


## 키보드 편집 및 컴포넌트 클립보드

Scene에서 객체를 클릭하거나 Hierarchy에서 선택한 뒤 사용한다.

| 키 | 동작 |
|---|---|
| Ctrl+Z | 되돌리기 |
| Ctrl+Y | 되돌리기 취소(다시 실행) |
| Ctrl+C | 선택 객체와 자식, 모든 등록 컴포넌트의 값 복사 |
| Ctrl+X | 복사 후 선택 객체와 자식 삭제 |
| Ctrl+V | 새 ID로 붙여넣기. 복사 시점의 월드 위치를 유지 |
| Delete / Backspace | 선택 객체와 자식 삭제 |

문자열 입력·숫자 편집·Transform 핸들 드래그·팝업 메뉴가 활성화된 동안 객체 단축키를 처리하지 않는다. 텍스트 입력에서는 기존 텍스트용 복사·잘라내기·붙여넣기·삭제가 동작한다. Play 모드에서는 객체 단축키를 사용하지 않는다.

Inspector의 컴포넌트 제목을 우클릭하면 Copy component, Copy all components, Paste component(s), Delete component 메뉴가 표시된다. 개별 복사는 해당 타입의 모든 등록 속성 및 Enabled를, 전체 복사는 Transform과 부착된 모든 등록 컴포넌트를 값과 함께 복사한다. 붙여넣을 대상에 같은 타입이 있으면 인스턴스를 추가하지 않고 속성만 덮어쓰며, 없으면 새로 부착한다. 대상의 관련 없는 컴포넌트는 유지한다. Transform은 삭제할 수 없다.

각 붙여넣기·잘라내기·삭제는 Undo 한 단계다. 객체 클립보드와 컴포넌트 클립보드는 별도로 유지되며 편집기를 종료하면 사라진다. OS 텍스트 클립보드에는 객체 데이터를 쓰지 않는다. 복사 후 원본을 수정·삭제해도 이미 복사된 값은 유지된다. 동일한 씬이면 원래 부모를 유지하고, 씬 교체 등으로 부모를 유지할 수 없으면 루트에 원래 월드 위치로 붙인다. 자식 관계는 새 ID로 다시 연결한다.

복사되는 값의 범위는 저장 기능과 같다. 에셋 참조는 ID로 공유하며 GPU 리소스·FMOD 채널·함수 콜백 같은 런타임 자원 자체는 복제하지 않는다. 객체 참조를 보관한 커스텀 문자열 속성의 ID는 자동 재매핑하지 않는다.

## Hierarchy / Scene 선택과 자식 조작

- Hierarchy와 Scene(View)은 선택 상태를 공유합니다. 선택 행을 강조하고 선택 객체마다 Transform 핸들을 표시합니다. Game 탭은 실행 화면입니다.
- Shift + 좌클릭: 추가 선택. 일반 좌클릭: 단일 선택. Scene 빈 공간 클릭: 해제. 선택된 자식의 조상 트리는 자동으로 펼쳐집니다.
- Delete / Backspace: 선택 객체와 자손을 일괄 삭제. Ctrl+Z 한 번으로 복원합니다. Inspector는 마지막으로 선택한 객체를 편집하고, 각 핸들은 해당 객체를 조작합니다.
- 자식 월드 Transform은 부모 월드 행렬 × 자식 로컬 행렬입니다. 이동·회전·크기를 재귀 상속합니다.

Hierarchy 행 또는 Scene 객체를 우클릭하면 커서 위치에 메뉴가 열립니다. 면 중심 원에서는 기존 우클릭 회전이 우선하므로 메뉴를 열 때는 객체 몸체를 우클릭합니다.

| 메뉴 | 동작 |
| --- | --- |
| Select All Children | 대상 및 모든 자손 선택 |
| Copy Object | 대상과 자손, 컴포넌트 값 복사 |
| Copy All Components | 대상의 모든 컴포넌트와 Transform 값 복사 |
| Paste All Components | 대상에 붙여넣기. 동일 타입은 값 갱신, 없는 타입은 추가 |
| Clone | 같은 부모 아래, 같은 위치에 자손까지 복제. 기존 클립보드 유지 |
| Reproduce | 빈 자식 생성. 로컬 위치/회전 0, 크기 1 |
| Control Children / Ctrl+T | 직접 자식들을 새 Group으로 묶고 해당 객체 아래에 배치 |

Control Children은 실제 Group 오브젝트를 생성합니다. 해제는 생성된 Group의 Ungroup을 사용합니다. 복사·붙여넣기 메뉴는 우클릭한 객체 하나에 적용하고, 일괄 삭제는 전체 선택에 적용합니다. 실행 모드에서는 편집 메뉴를 비활성화합니다.


## Group / Ungroup

여러 객체를 Shift+클릭으로 선택한 뒤 **Ctrl+G** 또는 우클릭 메뉴의 **Group**을 사용합니다. 하나만 선택해도 그룹을 만들 수 있습니다. 선택에 부모와 자손이 함께 있으면 부모만 그룹의 직접 멤버로 연결하여 변환의 중복 적용을 방지합니다.

- Group은 Hierarchy에 `[Group]` 표시가 있는 실제 오브젝트입니다. Inspector에서 이름, Transform, 컴포넌트를 편집할 수 있습니다.
- 생성 시 멤버들의 월드 경계 상자 중앙을 그룹 원점으로 설정합니다. Inspector의 `Group world size`는 전체 멤버가 차지하는 월드 축 정렬 경계의 크기입니다. Transform의 Scale은 이 크기에 적용되는 배율이며, 경계는 멤버 변경에 따라 갱신됩니다.
- 그룹 핸들로 이동·회전·크기를 바꾸면 모든 멤버의 월드 Transform에 반영됩니다. 그룹 변경은 각 멤버의 로컬 TRS 숫자를 매 프레임 덮어쓰지 않고 결합 행렬로 전달합니다.
- 원래 Parent 연결과 Group 연결을 함께 보존합니다. Hierarchy에는 그룹 아래에 표시하고 Inspector의 `Original parent`에서 원래 부모를 확인합니다. 공통 조상의 변환은 한 번만 적용합니다.
- Group을 다른 Group과 다시 묶어 중첩할 수 있습니다. Scene에서 그룹 내부를 클릭하면 가장 바깥 그룹이 선택됩니다. 개별 멤버나 내부 그룹은 Hierarchy에서 선택합니다.
- Hierarchy에서 대상 행으로 드래그하거나 Inspector의 Parent를 변경해 그룹을 다른 객체 아래로 옮깁니다. 이동 순간 월드 위치는 유지하며 이후 새 부모 좌표를 따라 움직입니다. Group 행으로 옮기면 그룹 멤버로 연결됩니다. Root로 이동하려면 Inspector의 Parent에서 Root를 선택합니다.
- **Ctrl+Shift+G**, 그룹 우클릭의 **Ungroup**, Inspector의 **Ungroup**은 그룹만 제거하고 멤버들의 현재 월드 모양과 위치를 보존합니다. 기존 부모/이전 그룹으로 돌아가며, 그룹에 직접 붙였던 컴포넌트는 그룹과 함께 제거됩니다. 그룹을 Delete하면 멤버도 함께 삭제됩니다.
- **Control Children / Ctrl+T**는 선택 객체의 직접 자식들을 묶어 그 객체 아래에 Group을 생성합니다. 자식이 없으면 아무 작업도 하지 않습니다. Release Children과 Ctrl+Shift+T는 제거되었습니다.

그룹 생성·해제·부모 변경은 Undo/Redo를 지원합니다. 그룹 링크와 비균일 크기 변경에 따른 affine 보정 행렬은 씬 저장, 플레이, 복제에 포함됩니다. 0 크기 등 역행렬을 구할 수 없는 Transform에서는 그룹 생성/공간 변경을 거부합니다. 그룹 크기는 메시/스프라이트/콜라이더 경계를 사용하며 투명 이미지 픽셀 경계는 계산하지 않습니다.


### 편집 모드 드래그 프리뷰

게임을 실행하지 않아도 Scene 핸들 조작은 즉시 반영됩니다. 편집 전용 Transform 프리뷰를 적용하고 같은 프레임에 View를 다시 렌더링하며, 게임의 Start/Update, 물리 시뮬레이션을 호출하지 않습니다. 편집 결과는 이후 Play를 시작할 때 초기 씬에 반영됩니다. Play 중에는 이 프리뷰로 실행 씬을 변경할 수 없습니다.

면 원의 우클릭은 다른 객체가 앞에 겹쳐 있어도 핸들이 우선합니다. 드래그 시작부터 버튼 해제 프레임까지 객체 메뉴 입력을 차단합니다. Shift로 회전을 시작하지 않는 경우에도 핸들 위 우클릭은 메뉴에 전달하지 않습니다. 원과 사각형의 표시 반경은 각각 3.5px, 2.5px로 줄였고 클릭 판정 반경은 기존 10px, 8px를 유지합니다. Escape 또는 View 탭 숨김/포커스 상실로 취소하면 시작 Transform으로 복구합니다. 마우스가 View 경계 밖으로 나가더라도 버튼을 잡고 있는 드래그는 계속됩니다.


### 이동 중 면 접촉 보정

면 중심 원을 좌클릭 드래그할 때 이동 객체의 면이 다른 객체의 평행한 면에 닿으면 접촉 위치에 고정합니다. 접촉 전에는 당겨 붙이지 않으며, 원래 마우스 이동량이 접촉 지점을 지난 **화면상 0~10픽셀** 구간에서는 접촉을 유지합니다. 정확히 +10픽셀까지 유지하고 +10픽셀을 넘으면 원래 드래그 위치로 돌아갑니다.

고정 구간을 벗어난 후 역방향으로 움직일 때는 같은 면에 다시 고정되지 않아 미세 조정이 가능합니다. 접촉 지점의 바깥쪽으로 돌아간 뒤 다시 진입하면 보정이 재활성화됩니다. 접촉면을 따라 옆으로 움직일 수 있고, 실제 면 영역을 벗어나면 고정을 해제합니다. 이동은 처음 선택한 드래그 평면을 계속 따릅니다.

Mesh/Sprite/BoxCollider의 경계 면을 사용하며 그룹은 멤버의 실제 경계 면들로 판정합니다. 회전·비균일 크기·shear를 고려하고, 평행하지 않은 면이나 영역이 겹치지 않는 면에는 보정하지 않습니다. 자기 자신/함께 움직이는 자손/비활성 객체는 접촉 대상에서 제외합니다. 보정은 편집 드래그에만 적용되며 물리나 게임 업데이트를 실행하지 않습니다. 드래그 한 번은 Undo 한 번으로 되돌립니다.

이동 보정 거리는 현재 View의 화면 좌표에서 계산합니다. 카메라 확대·축소, 원근/직교 투영, View 크기에 관계없이 마우스 기준 10픽셀로 유지됩니다.

우클릭 원형 드래그는 ±180도 경계를 넘어 계속 회전할 수 있으며 역방향 회전도 지원합니다. 중심 가까이 지나면 현재 각도를 유지하고, 다시 바깥으로 나온 위치를 새 기준으로 삼아 갑작스러운 회전을 방지합니다. 기존 90도 보정·역방향 미세 조정·메뉴 차단·Undo/Redo는 유지됩니다.

회전 드래그 중에는 선택 원과 반대편 원을 잇는 축을 금색 선으로 표시하고, 두 원도 금색으로 채워 강조합니다. 회전축 이름(X/Y/Z)을 함께 표시하여 정면에서 두 원이 겹쳐도 축을 확인할 수 있습니다. 버튼을 놓거나 회전을 취소하면 강조가 사라집니다. 원의 크기와 클릭 범위는 유지됩니다.

회전축 이름 옆에는 현재 보정 결과가 적용된 각도를 소수점 한 자리로 표시합니다(예: `Z rotation: 90.0 deg`). 일반 회전은 금색, 90도 보정에 고정된 동안에는 각도·축 선·양쪽 원이 민트색으로 바뀌며 `[SNAP]`을 표시합니다. 보정 범위를 벗어나거나 역방향 미세 조정 중에는 금색으로 돌아갑니다. 각도는 드래그 시작 축의 값에 누적한 회전량을 기준으로 하므로 복합 회전에서는 Inspector의 개별 Euler 값과 다를 수 있습니다.


## Movable: Camera / Object

상단 Movable 옆의 Camera와 Object는 독립적인 온오프 버튼입니다. 켜진 버튼은 강조색으로 표시됩니다. 기본값은 Camera 꺼짐, Object 켜짐입니다.

| 설정 | Scene 입력 |
| --- | --- |
| Camera만 켜짐 | 좌클릭 드래그: 화면 평면 이동, 우클릭 드래그: 제자리 회전. WASD 전후좌우, Q/E 하강·상승 |
| Object만 켜짐 | 기존 객체 선택, 우클릭 메뉴, Transform 핸들 조작 |
| 둘 다 켜짐 | Transform 핸들 우선. 핸들 밖 좌/우 드래그는 카메라만 조작. 짧은 클릭은 객체 선택/메뉴 |
| 둘 다 꺼짐 | Scene 좌/우 클릭과 드래그로 카메라/객체를 조작하지 않음 |

Object를 끄면 Scene의 객체 선택·우클릭 메뉴·Transform 핸들을 비활성화합니다. 기존 선택은 유지되고 Hierarchy/Inspector 편집은 계속 사용할 수 있습니다. Camera와 Object가 모두 켜져 있을 때는 4픽셀 이상 이동을 카메라 드래그로 판정하며, 짧은 클릭은 버튼을 놓을 때 실행합니다. 드래그가 끝나도 객체 메뉴가 추가로 열리지 않습니다. 포커스 상실/팝업/텍스트 편집 중에는 카메라 입력을 막습니다. 게임 카메라 및 오브젝트 Transform은 편집 카메라 이동에 영향을 받지 않습니다.

기존 공통 휠 기능은 두 토글과 별개로 유지합니다. 짧은 휠 클릭은 Camera 전용 ↔ Object 전용 상태로 빠르게 전환합니다. 두 버튼을 직접 누르면 둘 다 켜거나 끌 수 있습니다.

### 공통 휠 조작

Scene 위에서는 Move View / Move Object 모드와 관계없이 휠 버튼을 누르면 중앙에 십자 조준선이 표시됩니다. 조준선에 걸린 가장 가까운 렌더링 객체의 중심을 기준으로, 버튼을 누른 채 마우스를 움직이면 카메라가 그 주위를 회전합니다. 일반 휠 스크롤은 확대/축소 기능을 유지합니다. 객체 Transform과 Game 카메라는 바뀌지 않습니다.

휠 버튼을 드래그 없이 클릭하면 두 모드가 전환됩니다. 누른 위치에서 4픽셀 이상 움직인 제스처는 드래그로 확정하므로 원래 위치로 돌아와 버튼을 놓아도 모드를 전환하지 않습니다. 모드 전환은 버튼을 놓을 때 적용됩니다. 포커스 상실·Scene 숨김·Escape에서는 휠 제스처를 취소합니다. 진행 중인 객체 핸들 드래그와 겹치면 객체 드래그를 취소하고 카메라 입력을 처리합니다.


휠 회전 대상은 누르는 순간 고정됩니다. 조준선이 금색이면 선택된 대상의 중심을, 회색이면 월드 원점 (0, 0, 0)을 중심으로 회전합니다. 드래그 중 대상이 삭제되면 원점을 사용합니다. 드래그 중 다른 객체로 회전 기준이 바뀌지 않으며, 대상을 바꾸려면 버튼을 놓고 다시 누릅니다. 객체까지의 거리와 화면상의 상대 위치를 유지하므로 처음 회전할 때 카메라가 갑자기 중앙 정렬되지 않습니다. 위아래 회전은 극점 뒤집힘을 방지하도록 제한합니다. 휠 버튼을 놓으면 조준선이 사라집니다.

대상 판정은 활성 Mesh/Sprite 경계 상자를 사용합니다. 콜라이더만 있는 객체와 그룹의 빈 경계는 제외하고, 그룹 멤버는 실제 렌더링 객체로 판정합니다. 이미지의 투명 픽셀까지 구분하는 선택은 지원하지 않습니다.

사각형 크기 핸들은 잡은 쪽만 움직이도록 Scale과 Position을 함께 보정합니다. 객체가 회전하거나 부모/그룹에 비균일 크기가 적용되어 있어도 반대편 고정점은 유지됩니다. 한 번의 Undo로 위치와 크기가 함께 복원됩니다. Inspector에서 Scale 숫자를 직접 수정하는 동작은 기존과 같습니다.

모서리 핸들의 두 축은 비율로 묶이지 않습니다. 회전·비균일 부모 변환에서도 두 축의 배율을 따로 계산합니다. 해당 평면이 시선과 평행하여 교차점을 계산할 수 없을 때는 크기 변경을 보류하므로, 이 경우 카메라 각도를 바꾸어 조작합니다. 꼭짓점 핸들의 세 축 비례 조절은 유지합니다.


### 모서리 크기 조절의 10픽셀 접촉 보정

모서리 사각형을 드래그해 크기를 바꿀 때에도 다른 객체의 평행한 면에 닿으면 화면상 10픽셀까지 접촉을 유지합니다. 두 축은 독립적으로 보정되므로 한 축이 붙어 있어도 다른 축을 늘리거나 줄일 수 있고, 두 방향의 면에 동시에 붙일 수도 있습니다. 보정 중에도 반대 모서리는 고정됩니다.

10픽셀을 넘으면 해당 축의 보정을 해제하며, 해제 후 역방향 미세 조정과 접촉 지점 바깥으로 돌아간 뒤 재진입하는 동작은 이동 보정과 같습니다. 확대 배율에 관계없이 현재 화면에 투영한 핸들 위치로 거리를 측정합니다. 실제 면 영역이 겹치지 않으면 보정하지 않습니다. 이 보정은 2축 모서리 핸들에 적용하며, 3축 꼭짓점 비례 조절은 기존 동작을 유지합니다.

이동·모서리 크기 조절의 픽셀 보정 범위는 모두 10픽셀입니다. 접촉 고정 중에는 접촉한 양쪽 면을 반투명 민트색과 외곽선으로 강조하고, 조작 중인 원/사각형 핸들도 민트색으로 표시하며 `CONTACT SNAP` 문구를 보여줍니다. 두 축이 각각 접촉 중이면 두 접촉 쌍을 함께 표시합니다. 보정 해제·드래그 종료·취소 시 강조는 사라집니다. 이 표시는 에디터 오버레이이며 객체의 재질 색은 바꾸지 않습니다. 회전의 각도 보정 범위는 기존 ±5도를 유지합니다.


### Hierarchy 사이에 삽입

Hierarchy에서 객체를 드래그할 때 대상 행 중앙에 놓으면 그 객체의 자식으로 이동합니다(파란 테두리). 대상 행의 위·아래 가장자리로 가져가면 노란 삽입선이 표시되며, 놓으면 해당 객체와 같은 부모 아래의 앞·뒤 형제로 삽입됩니다. 펼쳐진 객체의 뒤에 넣는 경우에는 그 객체의 자손 목록 아래에 노란 선을 표시합니다.

최상위 객체 사이에 놓으면 Root 계층으로 이동할 수 있고, Group 안에서도 같은 방식으로 멤버 순서를 바꿀 수 있습니다. 기존 월드 위치·모양은 유지하며 변경 순서는 저장/불러오기 및 Undo/Redo에 포함됩니다. 자신 또는 자신의 자손 아래로 들어가는 순환 배치는 허용하지 않습니다. 실행 중에는 Hierarchy 드래그 편집을 비활성화합니다.


## 실시간 Light 이동

Light Inspector의 Type에서 **Point**를 선택하면 객체의 월드 위치가 광원 위치가 됩니다. 객체 또는 부모/그룹을 이동하면 다음 렌더링에 즉시 반영되며, Play를 실행하지 않아도 조명이 바뀝니다. Range는 빛이 영향을 주는 월드 거리이며 범위 끝으로 갈수록 부드럽게 감쇠합니다. Color와 Intensity도 실시간으로 반영됩니다.

**Directional**은 무한히 먼 방향광이므로 이동에는 영향을 받지 않고 방향 및 월드 회전에 따라 조명이 달라집니다. 기존 버전 1·2 씬의 Light는 위치로 조작할 수 있도록 Point, Range=10 기본값으로 불러오며 기존 색상·세기·방향 값은 유지합니다. 예전 방향광 표현을 유지하려면 Type을 Directional로 지정합니다.

동시에 최대 8개의 활성 Light를 지원합니다. 이 조명은 MeshRenderer에 적용되며 SpriteRenderer는 기존 비조명 표시를 유지합니다. 그림자와 차폐 계산은 아직 지원하지 않습니다.

Directional Light의 방향은 객체 및 부모/그룹의 Rotation만 합성하여 계산합니다. Position과 Scale(비균일·음수·0 포함)은 방향을 바꾸지 않습니다. 이전의 Scale에 따라 조명 방향이 달라지던 계산 오류를 수정했습니다.

## 메시 재질 조절

Inspector에서 MeshRenderer의 Color를 정한 뒤 바로 아래의 **Add Material**을 누릅니다. Scene과 Game 뷰에서 조정 결과를 볼 수 있습니다. 반사광을 확인하려면 메시 앞에 Point 또는 Directional Light를 배치합니다.

- **Metalicity**는 0에서 비금속, 1에서 금속입니다. 금속에 가까울수록 반사광에 바탕색이 나타납니다.
- **Roughness**가 낮으면 반사광이 좁게 모이고, 높으면 넓게 퍼집니다. 기본값은 각각 0과 0.5입니다.
- **Albedo texture**에서 프로젝트 이미지를 선택하면 메시 색상과 이미지를 곱한 값이 바탕색이 됩니다. None을 선택하면 색상만 사용합니다.
- Material의 Enabled를 끄면 기존 메시 조명으로 돌아갑니다. SpriteRenderer는 기존의 비조명 방식으로 표시합니다.

## Create object 탭

Hierarchy의 Create object 버튼을 누르면 생성 종류를 선택하는 팝업이 열립니다. 생성한 오브젝트는 자동으로 선택되며 Ctrl+Z로 생성을 취소할 수 있습니다.

- Basic shapes에서 Cube, Circle, Rectangle, Sphere, Cylinder, Cone을 생성합니다. Circle과 Rectangle은 XY 평면이며 나머지는 입체 메시입니다. Inspector의 MeshRenderer Shape로 도형을 변경할 수 있습니다.
- Sprite의 2D Image는 SpriteRenderer를 생성합니다. Inspector의 Choose image에서 프로젝트 이미지를 선택합니다.
- Monkey Script 탭의 Object는 ObjectScript가 붙은 빈 오브젝트입니다.
- Singleton Manager는 활성 매니저가 있으면 그 오브젝트를 선택하고, 없으면 생성합니다.
- Blank Script는 BlankScript와 단위 BoxCollider를 붙인 투명 큐브 영역입니다. 선택하면 큐브 형태의 변형 핸들이 나타납니다.

세 유형 모두 Inspector에 **Monkey Script**로 표시됩니다. **Open RiceMonkey**에서 동작을 편집하고 **Save**로 프로젝트의 `Scripts` 폴더에 저장하면 다음 Play부터 적용됩니다. **Open in C++**를 누르면 같은 파일이 지정한 C++ 편집기에서 열립니다.

회전 스냅은 한 번의 드래그에서도 0, 90, 180, 270, 360도 및 이후 모든 90도 간격에 반복 적용됩니다. 다음 구간으로 갔다가 이전 구간으로 돌아오면 이전 구간의 스냅도 다시 활성화됩니다. 스냅 해제 직후 같은 구간에서 역방향으로 움직이면 중심 각도까지 미세 조절할 수 있습니다.

## 큐브맵 전개도 적용

MeshRenderer의 Shape가 Cube인 오브젝트에 Material을 추가하고 Albedo / Cubemap에서 프로젝트 이미지를 선택합니다. 이미지 크기에 따라 3×4 세로 십자, 4×3 가로 십자, 6×1 가로 띠, 1×6 세로 띠를 자동 판별합니다. 각 칸은 정사각형이어야 합니다. Inspector의 Detected 표시에서 감지 결과를 확인합니다.

띠 배치는 첨부 예시와 같이 +X, -X, +Y, -Y, +Z, -Z 순서입니다. 세로 십자는 가운데가 +X이고 아래 끝은 -X입니다. 가로 십자는 가운데가 +Z이고 오른쪽 끝은 -Z입니다. 빈 칸은 샘플링하지 않습니다. 일반 비율의 이미지는 기존 2D 텍스처로 사용합니다.

배포 패키지의 기본 프로젝트에 기본 크기 1×1×1의 Grass Cube를 추가했습니다. 이 기능은 전개도를 큐브 표면에 입히는 재질 매핑입니다.


## 동적 Reflection Probe 설정

Inspector에서 Add ReflectionProbe를 누르면 동적 반사를 활성화할 수 있습니다. 프로브 오브젝트의 월드 위치에서 주변을 여섯 방향으로 촬영합니다. 프로브가 붙은 오브젝트는 촬영에서 제외됩니다. 반사할 오브젝트에는 활성 Material을 붙이고 Metalicity와 Roughness를 조절합니다.

- Cubemap resolution은 면별 저장 해상도입니다. 16~2048 중 선택하며 기본값은 256입니다. 해상도가 높을수록 메모리와 촬영 비용이 증가합니다.
- Mipmap storage quality의 RGB8은 채널당 8비트, RGB16F는 채널당 16비트 부동소수점 HDR 저장입니다. 모든 mipmap 단계에 같은 포맷을 사용하며 기본값은 RGB8입니다. GPU 메모리에 저장합니다.
- Flat reflection below (px)는 단순 반사로 전환하는 픽셀 크기 기준입니다. 화면 경계의 너비와 높이 중 긴 쪽이 기준 미만이면 카메라 쪽을 향한 대표 면 하나를 반사 평면으로 사용합니다. 평면 위의 픽셀마다 반사 위치를 계산해 상의 모양과 위치를 유지합니다. 새 프로브 기본값은 100px입니다. 기준 이상이면 표면별 동적 반사를 사용합니다. 기존 Max object size 저장 값은 이 전환 기준으로 읽습니다. 0이면 모든 보이는 메시가 동적 반사를 사용합니다.
- Fix up edge seams는 GL_TEXTURE_CUBE_MAP_SEAMLESS를 켜거나 끕니다. 기본값은 켜짐입니다. 큐브 면 경계를 가로질러 텍스처를 필터링합니다.

활성 프로브마다 큐브맵을 별도로 저장합니다. 기준 이상인 오브젝트가 사용하는 프로브는 Scene 또는 Game 뷰 렌더링 때 여섯 면을 갱신합니다. 작은 오브젝트만 사용하면 마지막 큐브맵을 재사용합니다. 최초 사용 또는 해상도·포맷 변경 때는 작은 오브젝트도 한 번 촬영합니다. 오브젝트에 활성 ReflectionProbe가 붙어 있으면 자신의 프로브를 사용하고, 없으면 월드 위치에서 가장 가까운 활성 프로브를 사용합니다. 전환 기준과 저장 품질 및 경계 보정은 선택된 프로브의 설정을 따릅니다. 프로브가 많을수록 촬영 비용과 메모리가 증가합니다. 반사 안의 재귀 반사는 생략합니다. Roughness에 따른 흐림은 일반 mipmap 보간이며, GGX 환경맵 사전 필터링은 추가 구현이 필요합니다. 반사선과 장면 도형의 교차점을 구해 프로브 촬영 위치와 표면 위치의 차이를 보정합니다. 프로브에서 다른 물체에 가려져 촬영되지 않은 면과 투명 이미지의 빈 영역은 여전히 근사 오차가 생길 수 있습니다. Create grass cube 버튼은 제거했습니다.


반사상의 위치와 크기는 실제 반사 평면을 기준으로 계산합니다. Cube, Circle, Rectangle, Sphere, Cylinder, Cone 및 Sprite의 월드 변환을 반영하며, 작은 오브젝트에서도 반사상을 한 색으로 축약하지 않습니다. 갱신을 멈춘 프로브는 마지막 큐브맵과 당시 장면 도형 및 촬영 위치를 함께 보관합니다. 이 상태에서 주변 오브젝트를 움직이면 반사에는 마지막 촬영 장면이 유지됩니다.


## Camera와 Camera Follower

- Create object → Camera는 Camera 컴포넌트를 가진 오브젝트를 만듭니다. 기존 오브젝트에도 Add Component에서 Camera를 추가할 수 있습니다.
- Camera의 Primary를 켜면 Game 화면에서 사용합니다. 여러 개면 씬 순서상 첫 활성 Primary 카메라를 사용하며, 없으면 기존 기본 카메라를 사용합니다.
- LookAt (world)에 월드 좌표를 입력하고 Apply LookAt을 누르면 오브젝트의 rotation이 해당 지점을 바라보도록 바뀝니다. 전방은 로컬 -Z, 위치는 오브젝트 pivot입니다.
- 따라갈 오브젝트에 Camera Follower를 추가하고 Follow camera를 선택합니다. Enabled가 켜져 있으면 Play 중 스크립트와 물리 업데이트 이후 이 오브젝트가 카메라를 따라 움직입니다.
- Follower의 Translation / Rotation / Scale은 오브젝트 pivot을 원점으로 하는 로컬 프레임입니다. 이 프레임이 카메라의 위치·회전 프레임과 일치하도록 오브젝트를 배치합니다. 기본 transform이면 오브젝트 pivot이 카메라에 놓입니다.
- Shape Editor → General에서도 Follower를 추가·설정할 수 있습니다. 카메라 아이콘을 클릭하면 노란색으로 선택되고 pivot 좌표계의 X/Y/Z 이동 축이 나타납니다. 축을 왼쪽 버튼으로 드래그하면 해당 Translation 좌표만 변경됩니다. Esc로 드래그를 취소하고 Ctrl+Z / Ctrl+Y로 실행 취소·다시 실행할 수 있습니다. On in Shape Editor는 표시만 제어합니다. Save → in scene으로 씬에 적용합니다.
- 씬은 카메라 참조를 저장합니다. 독립 .riceshape 파일은 로컬 설정만 저장하므로 불러온 후 카메라를 선택해야 합니다. 삭제된 카메라, 순환 추적, 0 scale과 Anchor로 구속된 오브젝트는 추적을 적용하지 않습니다.

Play는 물리·스크립트·애니메이션을 시작한다. 상단 Pause는 현재 위치와 속도를 유지한 채 시뮬레이션과 오디오를 일시 정지하고, Resume은 같은 상태에서 이어간다. Stop은 실행을 끝내고 Play 이전의 편집 상태로 복원한다.

### Scene Settings

새 프로젝트와 빈 씬은 `Assets/Skybox/sky.png`를 기본 하늘로 사용한다. **Skybox asset**에서 `sf.png`나 `night.png`로 바꿀 수 있다. 씬을 복제하면 원본의 스카이박스 선택과 활성 상태를 함께 복사한다.

메인 편집기 상단의 **Settings → Scene**에서 씬별 환경을 설정한다. **Settings → Streaming**에서 YouTube Commands와 Cycle을 열고, **Settings → Script editor**에서 스크립트를 열 앱을 선택한다. Skybox 토글과 애셋 선택은 파노라마 또는 cubemap atlas 이미지를 사용한다. Default directional light는 별도의 오브젝트 없이 색상·강도·방향을 설정한다. Ground는 y=0의 연한 회색 무한 평면이며, Ground collision을 켜면 활성 Rigidbody와 비 Trigger BoxCollider를 가진 동적 물체를 지지한다. Kinematic은 기존처럼 지정한 이동을 유지한다.

X/Y/Z 축과 XY/YZ/ZX grid는 각각 켜거나 끌 수 있고 Scene 뷰에만 나타난다. Game 뷰, 반사 캡처, 독립 실행 플레이어에는 표시되지 않으며, 내보낸 씬 파일에서는 EditorGrid 설정도 제외된다. 환경 설정은 씬 저장·복제·Undo/Redo·Play/Stop에 함께 반영된다.
