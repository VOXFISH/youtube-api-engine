# RiceMonkey 전략 패턴 명세서

## 1. 목적과 적용 범위

게임 제작자는 **어떤 행동을 쓸지 정하는 행**과 **그 행동을 실행하는 행**을 따로 작성할 수 있다. 예를 들어 점수를 얻을 때마다 `Call Strategy → award`를 호출하고, 콤보 모드에 들어갈 때 한 번 `Change Strategy → award → ComboScore`를 실행한다. 점수를 주는 모든 위치에 콤보 조건을 반복해서 넣을 필요가 없다.

이 문서는 RiceMonkey의 기존 전략 교체 규칙을 구체화한 **구현 계획과 인수 기준**이다. 전략 슬롯은 한 시점에 한 행동을 선택한다. 한 게임에 점수·이동·대상 선택 슬롯을 함께 둘 수 있다. State의 `On Enter`에서 전략을 바꾸고 이후 `Update`에서 호출하는 조합도 가능하다. 사용자에게는 행동 이름, 입력, 결과가 보이고, 저장·컴파일·실행의 원본은 C++이다. 편집기에서 제공하는 문구는 영어로 표시한다. [상위 RiceMonkey 명세](Scripting.md)

### 현재 구현과 이번 작업

| 영역 | 현재 코드에서 확인한 동작 | 구현할 내용 |
|---|---|---|
| 실행 | `StrategySlot<Output, Args...>`, `MakeStrategy`, `Replace`, `Invoke`가 있다. 교체는 새 행동 객체를 만들고 실행 중인 호출은 자신이 시작한 객체를 보유한다. | 기존 SDK를 재사용하고 빈 슬롯·교체 실패를 편집기 행까지 연결한다. |
| 편집 | `Strategy → New Slot`, `Change Strategy`, `Call Strategy`가 있다. 슬롯은 변수이며 두 동작은 정해진 C++ 텍스트 형태의 `Custom` 행을 위젯이 해석한다. | 선언과 두 실행 행을 문서 모델에서 식별한다. 후보 필터, 참조 추적, 인수 편집, 진단이 같은 정보를 사용하게 한다. |
| 검증 | 기존 테스트에 전략 재선택, 대기 중인 호출의 교체, 편집기가 생성한 교체·호출 구문의 재해석 사례가 있다. | 세 게임 예제, 이름 변경과 삭제, 네이티브 저장 실패, 프리셋과 배포 실행까지 검증한다. |

근거는 [전략 런타임](../../Scripting/ScriptRuntime.h), [전략 편집 위젯](../../Editor/ScriptStrategyWidgets.inl), [실행기 테스트](../../Tests/ScriptRuntimeTests.cpp), [편집기 테스트](../../Tests/ScriptEditorTests.cpp)에서 확인할 수 있다.

## 2. 구현할 전략 예제

세 예제는 같은 슬롯·교체·호출 기능으로 작성한다. 예제별 전용 메뉴를 만들 필요 없이 일반 클래스와 함수로 새 후보를 더할 수 있어야 한다. 클래스마다 메서드 이름을 다르게 지어 스크립트 전체의 동명 선언 금지 규칙을 지킨다.

| 게임 동작과 슬롯 | 교체 가능한 행동 | 인수 예시와 기대 결과 |
|---|---|---|
| 점수 계산 `award` · `int → int` | `FlatScore::AwardFlat`은 기본 점수를 반환한다. `ComboScore::AwardCombo`는 멤버 `streak`를 0에서 시작해 호출마다 1 증가시키고 기본 점수에 곱한다. | 기본 점수 10으로 콤보를 두 번 호출하면 10, 20이다. 일반 점수로 바꾸면 10, 다시 콤보로 바꾼 첫 호출도 10이다. 확정된 점수를 저장하는 스크립트 멤버는 유지한다. |
| 이동량 계산 `movement` · `(vector 2, float) → vector 2` | `WalkMove::WalkStep`은 방향에 이동량을 곱한다. `DashMove::DashStep`은 결과를 두 배로 한다. | 방향 `(1, 0)`, 이동량 `3`이면 걷기는 `(3, 0)`, 대시는 `(6, 0)`이다. 이동 슬롯만 바꿔도 점수 슬롯의 콤보는 이어진다. |
| 대상 선택 `targetChoice` · `list<int> → int` | `FirstTarget::PickFirst`는 첫 원소의 인덱스, `StrongestTarget::PickStrongest`는 가장 큰 위협도의 인덱스를 돌려준다. 동점이면 먼저 등장한 원소를 고른다. | 위협도 `[2, 8, 8]`의 결과는 각각 0과 1이다. 빈 목록은 둘 다 `-1`을 반환하며 호출자는 인덱싱하기 전에 검사한다. |

첫 구현은 점수 예제를 편집기에서 작성해 실제 Player까지 실행하는 것을 목표로 한다. 다음 두 예제는 같은 경로가 여러 입력, 벡터 반환, 컨테이너 입력에도 적용되는지 확인한다.

## 3. 작성 흐름과 편집기 규칙

1. Inspector에서 `Open RiceMonkey`를 열고 `Class Editor`에서 후보 클래스와 메서드를 작성한다. 콤보 횟수처럼 선택을 유지하는 동안 보존할 값은 그 클래스의 멤버로 선언한다. 공유할 점수 합계는 스크립트 멤버로 둔다.
2. 정의부의 `+ → Strategy → New Slot`에서 기준 메서드를 고른다. 스크립트의 `Variables`에 슬롯 선언 한 개를 만들고 해당 행으로 이동해 이름을 입력한다. 정의부의 실행 행 수는 그대로다. 기준 메서드는 입출력 형식을 정하는 데 사용하며 초기 슬롯은 비어 있다.
3. `Start`에서 `+ → Strategy → award → Change Strategy`를 선택하고 `Behaviour`에 `ComboScore::AwardCombo`를 지정한다. 이 행이 **실행될 때** 행동을 생성한다. 상태 전환이나 조건 분기 안에도 교체 행을 둘 수 있다.
4. 점수를 받을 위치에 `+ → Strategy → award → Call Strategy`를 추가한다. 인수를 선언 순서대로 입력하고 `Output`에서 결과를 받을 변수를 고른다. 값이 필요 없으면 `Discard`를 선택한다. 반환형이 `void`이면 `Output` 자체를 숨긴다.

| 편집 대상 | 표시와 검증 |
|---|---|
| 슬롯 선언 | `Strategy`, 슬롯 이름, 입력의 순서와 형식, 반환형을 표시한다. 초보자용 표기는 `Inputs (int) → Output int`와 같이 한다. 초기 슬롯이 비어 있는 것은 정상이다. 슬롯은 스크립트 컴포넌트별 멤버이며 RiceCon 값으로 내보내지 않는다. |
| 후보 | 현재 문서의 최상위 작성 클래스에 직접 선언된, 호출 위치에서 접근 가능한 인스턴스 메서드를 대상으로 한다. 동일 문서에서 연결 가능한 기존 작성 메서드를 유지한다. 외부 클래스는 기존 가져오기나 프리셋으로 문서에 포함한 뒤 선택한다. 후보명은 `Class::Method`로 표시한다. |
| 호환성 | 반환형, 매개변수 개수, 순서별 값 형식이 모두 일치해야 한다. 이름·공백·기본 인수 표기는 호환성에 영향을 주지 않는다. `Task<int>` 메서드의 논리 반환형은 `int`다. `int` 후보를 `float` 반환 슬롯에 자동 연결하지 않는다. 동기 메서드와 코루틴 메서드는 SDK로 실제 호출할 수 있을 때 같은 후보가 된다. |
| 입력과 출력 | 매개변수 이름이 있으면 `basePoints (int)`처럼, 후보별 이름이 다르거나 이름을 복원할 수 없으면 `Argument 1 (int)`처럼 표기한다. 기본 인수가 있어도 모든 입력 칸을 표시한다. 입력 식에는 기존 변수·백틱 검색·숫자 변환 규칙을 적용한다. 출력 후보는 현재 범위에서 쓸 수 있는 반환형과 같은 형식의 변수다. 읽기 전용 후손은 출력 후보에서 제외한다. |
| 호출 위치 | `Call Strategy`는 보류 가능한 `Start`, `Update`, 함수 본문과 그 안의 분기·루프에서 사용한다. 클래스의 `On Create / On Destroy`, 상태의 `On Enter / On Update / On Exit`, IDE에서 작성한 일반 동기 함수에서는 비활성화한다. 그 문맥에서도 동기적으로 끝나는 `Change Strategy`를 배치할 수 있다. |

목록에서 지원하는 형식은 RiceMonkey 기본 값, 컨테이너와 서명에서 식별할 수 있는 사용자 값 클래스다. 중첩 템플릿·한글 이름·쉼표가 포함된 식은 C++ 토큰의 중첩을 따라 분리한다. 포인터, 참조 수명, 오버로드 선택, 멤버 한정자 등으로 현재 SDK가 안전하게 연결할 수 없는 네이티브 선언은 후보에서 제외한다. 유효한 원문은 `Custom Code`로 보존한다.

## 4. 실행과 수명

| 시점 | 관찰 가능한 결과 |
|---|---|
| 첫 선택과 재선택 | 교체 행에서 인스턴스를 새로 만든다. 같은 행동을 다시 선택해도 멤버는 선언 초기값에서 시작한다. 두 슬롯이 같은 클래스를 선택하거나 두 오브젝트가 같은 스크립트를 사용해도 행동 인스턴스는 각각 독립적이다. |
| 한 프레임에 여러 번 교체 | 실행 순서대로 모두 적용한다. `Change A → Call → Change B → Call`의 결과는 각각 A와 B다. 교체 사이에 호출이 없어도 각 교체 행의 생성 동작은 실행된다. |
| 호출과 대기 | 호출 시점에 선택된 행동을 고정하고 인수를 값으로 전달한다. 그 행동이 `Wait`하거나 루프 예산을 소진하면 호출자도 같은 위치에서 보류된다. 출력은 성공적으로 반환한 순간 한 번 기록한다. 다른 컴포넌트는 계속 진행한다. |
| 대기 중 교체 | A가 실행 중에 슬롯을 B로 바꾸고 `Wait(0)`한 경우, 다음 틱에 이미 시작한 호출은 A의 지역값·멤버로 완료된다. 이후 새 호출은 B를 사용한다. A의 슬롯 소유권과 마지막 실행 중 호출이 모두 끝난 시점에 A가 한 번 소멸한다. |
| 생성 실패 | 새 행동을 성공적으로 만든 뒤 슬롯에 게시한다. 생성 실패 시 슬롯에는 이전 선택이 남는다. 이미 실행한 생성 콜백의 외부 쓰기는 유지된다. 실행 오류 처리는 아래 기준을 따른다. |
| Pause·Stop·재생 | Pause 또는 외부 비활성화 동안 보류된 호출의 시간이 멈춘다. Stop·컴포넌트 파괴 시 보류 호출을 취소하고 행동을 정리한다. 대기 다음 행과 출력 쓰기는 실행하지 않는다. 다음 Play는 빈 슬롯으로 시작해 `Start`의 선택을 다시 실행한다. |

**오류 처리.** 빈 슬롯 호출 자체는 편집 시 언제나 오류인 것은 아니다. 인게임 조건에 따라 앞선 행에서 선택할 수 있기 때문이다. 실제로 빈 슬롯을 호출하면 `Choose a strategy first.`를 Error로 기록하고 호출 행·소유 함수·창과 Inspector에 표시한다. 출력 변수에는 이전 값이 남는다. 처리되지 않은 실행 오류는 기존 스크립트 실행기 규약대로 해당 컴포넌트의 실행을 중지한다. 다른 컴포넌트와 Play는 계속된다. 잘린 참조, 호환되지 않는 후보, 인수 개수 오류는 Save 시 행 위치와 함께 알려주고 마지막 컴파일 성공본을 유지한다.

## 5. 주요 구현 객체와 C++ 원문

| 객체 | 보유할 정보 | 담당 기능 |
|---|---|---|
| `ScriptDocument`와 `ScriptNode` | 기존 항목 ID, 소유 범위, 원문 구간. 슬롯에는 반환형·순서 있는 입력형, 교체 행에는 슬롯·클래스·메서드 참조, 호출 행에는 슬롯·인수 식·선택적 출력 참조를 둔다. | 기존 변수 선언을 전략 슬롯으로 식별하고 교체·호출을 전용 행으로 해석한다. 추가·이동·삭제·이름 변경 후 ID와 원문을 함께 갱신한다. `Class::Method` 참조도 사용 횟수와 `Find Instances`에 포함한다. |
| `ScriptPanel`의 전략 위젯 | 현재 창의 선언·후보·선택 행과 진단. 형식 및 접근성 판정은 문서 모델 결과를 사용한다. | `New Slot`, `Change Strategy`, `Call Strategy`를 편집하고 입력·출력 후보를 필터링한다. 참조가 끊기면 원래 이름을 빨간색으로 유지해 다시 선택할 수 있게 한다. |
| `StrategySlot`과 `MakeStrategy` | 컴포넌트의 현재 호출 대상, 행동 생성 방법, 진행 중인 호출이 보유한 인스턴스. | 메서드를 호출 가능한 행동으로 감싸고 교체 성공 시 게시한다. 대기·취소·소멸은 기존 `Task`와 컴포넌트 실행기를 사용한다. 사용자에게 포인터·인터페이스·상속 선언을 요구하지 않는다. |
| 기존 저장·실행 경로 | C++ 원문, 마지막 성공 모듈, 현재 Play가 사용하는 버전, 실행 오류의 파일과 행 ID. | Save 시 검증·컴파일한다. 실행 오류를 전략 행으로 돌려보낸다. IDE 편집·프리셋 복사·독립 실행 게임 내보내기는 기존 RiceMonkey 경로를 사용한다. |

다음은 점수 예제에서 슬롯 선언, `Start`의 선택, 점수 처리 함수의 호출이 각각 만드는 **C++ 구간**이다. `ComboScore`는 같은 스크립트에서 작성한 클래스, `lastAward`는 선언된 정수 변수다.

```cpp
// Script member
StrategySlot<int, int> award;

// Inside Start
award.Replace(MakeStrategy(*this, &ComboScore::AwardCombo));

// Inside a coroutine handling the score
static_cast<void>(lastAward = co_await award.Invoke(10));
```

목록과 AI가 수정하는 대상은 이 C++ 파일 하나다. 기존 편집기가 출력한 호출·대입·클래스 소유자 표기와 선택적 ID 주석을 읽을 수 있어야 한다. 공백이나 주석만 바꾼 경우 같은 행으로 복원하고, 문자열이나 주석 속의 `Invoke`는 사용처로 세지 않는다. 원문을 해석할 수 없는 유효한 C++ 구간은 해당 바이트를 보존한다. 선언 삭제 후 같은 이름으로 새 선언을 만들어도 ID가 다른 기존 참조는 사용자가 다시 지정할 때까지 오류로 남는다. 마지막 사용 행을 삭제해도 선언은 수동 삭제할 때까지 남는다.

**저장과 프리셋.** IDE와 분리 창에서 서로 다른 행을 고치면 양쪽 변경을 보존하고 같은 행은 최근 편집을 적용한다. IDE 저장은 목록을 갱신한다. 명시적 Save 성공본은 다음 Play에 적용한다. `Save as Preset`은 성공본의 C++ 텍스트를 복사하므로 슬롯 선언과 교체·호출 행이 복사된다. 실행 중인 콤보 횟수, 중단된 호출, 다른 컴포넌트의 Scene 바인딩은 복사 대상에 들어가지 않는다. 불러온 코드의 외부 대상·정책은 새 문맥에서 연결해야 한다. ## 6. 구현 순서

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 1. 기존 C++ 호환 고정 | 현재 SDK·위젯이 생성하는 슬롯, 스크립트/클래스 내부 교체, 출력 저장/폐기 구문을 회귀 입력으로 확보한다. | 기존 파일을 열어 편집하지 않고 닫으면 원문이 동일하다. 기존 재선택·대기 중 교체 테스트가 통과한다. |
| 2. 문서 모델과 참조 | 슬롯 서명과 교체·호출 행을 토큰으로 해석한다. 기존 ID·형식 비교·범위 검사·진단을 재사용하고 편집기 전용 문자열 판정을 대체한다. | 한글 매개변수와 중첩 컨테이너를 복원한다. 이름 변경·삭제·동명 재생성·미사용 경고를 모델 테스트에서 판정한다. |
| 3. 점수 예제의 전체 작성 흐름 | 선언부 이동, 호환 후보 선택, 입력·출력 위젯, `Find Instances`, 동기 문맥의 호출 제한을 연결한다. | 작성자가 C++를 열지 않고 점수 예제를 만든다. 생성된 파일을 네이티브로 컴파일해 `10 → 20 → 10 → 10`을 얻는다. |
| 4. 실행 행 진단과 수명 | 빈 슬롯·생성 실패를 원래 행에 매핑하고, 인스턴스 분리·대기 중 교체·취소 시 출력과 소멸 시점을 검증한다. | 아래 실행 기준을 편집기 Play와 실제 C++ 모듈로 재현한다. |
| 5. 다른 전략과 배포 | 이동·대상 선택 예제를 같은 위젯으로 작성한다. 프리셋 복사, 외부 편집, 실패 후 재생, 독립 실행 게임 내보내기를 확인한다. | 세 예제가 추가 런타임 분기 없이 동작하고 배포 게임의 결과가 편집기와 일치한다. |

## 7. 인수 기준

| 번호 | 조작과 관찰 결과 | 검증 경로 |
|---|---|---|
| A1 | `Update`의 `New Slot`을 누르면 포커스가 스크립트 선언부로 이동하고 실행 행 수는 늘지 않는다. 이전 C++의 교체·호출은 다시 열었을 때 각각 한 행으로 복원된다. | `ScriptAuthoring`, `ScriptEditor` |
| A2 | `int(int)` 슬롯에는 이름이 다른 두 점수 행동이 모두 나타난다. 반환형·매개변수 순서·개수가 다른 후보는 제외된다. `void`에서는 출력란이 숨고, 값 반환 호출에서 `Discard`를 선택해도 행동은 한 번 실행된다. | `ScriptEditor`, 네이티브 실행 |
| A3 | 점수 예제의 결과는 `10, 20, 10, 10`이다. 같은 콤보를 다시 선택해도 다음 결과는 10이다. 같은 파일을 연결한 두 번째 컴포넌트의 첫 결과도 10이다. | `ScriptRuntime`, `ScriptNativeSaveAndPlay` |
| A4 | 이동량은 각각 `(3, 0)`, `(6, 0)`이다. 이동 전략을 바꾸기 전후 점수 콤보는 이어진다. 대상 전략은 `[2, 8, 8]`에서 0 또는 1, 빈 목록에서 `-1`을 반환한다. | 세 예제를 저장해 네이티브 실행 |
| A5 | 행동이 내부 횟수를 1 올리고 자신을 새 인스턴스로 교체한 뒤 `Wait(0)`을 거쳐 ‘입력 + 자기 횟수’를 반환한다. 입력 10, 20의 결과는 각각 11, 21이며 합은 32다. 별도 사례에서 대기 중 Stop하면 출력 쓰기 0회, 이미 생성한 각 행동의 소멸은 1회다. | `ScriptRuntime`, DLL 수명 테스트 |
| A6 | 빈 슬롯 호출은 해당 행에 Error를 하나 남기고 출력 초기값을 유지한다. 생성 실패를 일으킨 SDK 단위 테스트에서는 이전 대상을 그대로 호출할 수 있다. 처리되지 않은 오류가 있는 컴포넌트와 동시에 실행한 정상 컴포넌트는 계속 진행한다. | `ScriptRuntime`, `ScriptEditor` |
| A7 | 교체 행에서만 선택한 메서드에도 사용처가 잡힌다. 교체 행을 삭제하면 메서드는 남고 다음 Save에서 미사용 경고가 발생한다. 메서드를 삭제하고 동명 메서드를 만들어도 기존 행은 빨간색이며 명시적으로 다시 선택하면 복구된다. | `ScriptAuthoring`, `ScriptEditor` |
| A8 | IDE에서 한 행의 인수를 10에서 20으로, 분리 창에서 다른 행의 후보를 바꾸면 둘 다 남는다. 잘못된 형식으로 Save하면 위치를 표시하고 이전 성공본이 실행된다. 수정본 저장 후 다음 Play부터 새 결과가 나온다. | `ScriptEditor`, `ScriptNativeSaveAndPlay` |
| A9 | 새 컴포넌트에서 점수 프리셋을 불러와 `Save As...`로 별도 C++ 파일에 저장한다. 다음 Play에서 복사본의 첫 콤보는 10이다. 원본을 수정해도 복사본의 소스는 유지된다. 프로젝트를 독립 실행 게임으로 내보내면 편집기와 같은 입력·결과 순서가 재현된다. | 프리셋 재개방, 독립 실행 게임 |

## 8. 구현 전 논의할 사항

| 결정할 내용 | 이 계획의 기본안과 영향 |
|---|---|
| 새 슬롯에 첫 전략을 지정하는 편의 기능이 필요한가? | 첫 버전은 기존처럼 빈 슬롯으로 선언하고 `Start`의 교체 행으로 초기 행동을 설정한다. 이후 단축 동작을 넣더라도 실행 시점이 보이도록 실제 교체 행을 만들어야 한다. |
| 예제를 사용자가 불러오는 프리셋으로 함께 제공할 것인가? | 세 예제는 인수용으로 작성하고, 배포 후보는 점수 프리셋 하나로 시작한다. 배포를 선택하면 기존 `Load Preset...`으로 열 수 있는 C++ 파일과 한 번의 재생으로 결과를 확인할 장면을 제공한다. |
| 서로 다른 스크립트의 전략을 직접 연결해야 하는가? | 첫 버전은 현재 문서에 포함된 클래스 기준으로 호환성을 판정한다. 파일 간 실시간 연결이 필요하면 별도 단계에서 외부 선언의 안정적인 식별, 파일 이동, 저장·재컴파일 순서를 결정한다. |
