# RiceMonkey 명세서

초보자는 Rice의 목록으로 게임 동작을 작성하고, AI와 지정 IDE는 **C++ 원문을 직접 수정**한다. 실행 대상은 표준 C++다. 편집기는 같은 스크립트를 목록으로 보여주며, 사용자가 별도 언어나 포인터·상속 문법을 익히지 않아도 게임을 만들 수 있어야 한다.

편집기의 버튼, 메뉴, 안내, 경고, 오류, 빈 검색 결과와 키보드 도움말은 모두 영어로 표시한다. 사용자가 지은 이름과 입력한 내용은 그대로 보존한다.

## 1. 스크립트 컴포넌트와 편집 창

**컴포넌트 하나는 스크립트 파일 하나에 연결된다.** Hierarchy에서 스크립트 오브젝트를 만들거나 Inspector에서 스크립트 컴포넌트를 추가할 때 `Object`, `Singleton Manager`, `Blank Script` 중 하나를 선택한다. 생성 후에는 모두 `Monkey Script`로 표시하고 생성 유형은 읽기 전용으로 유지한다.

- **생성 유형별 동작** — 기존 Singleton의 씬별 인스턴스 조회를 보존한다. Hierarchy에서 Singleton Manager를 생성할 때 활성 매니저가 있으면 그 오브젝트를 선택한다. Blank Script 오브젝트를 생성할 때는 기존처럼 `BoxCollider`를 함께 추가한다.
- **메인 창** — Inspector의 `Open RiceMonkey`를 누르면 해당 스크립트의 편집 창이 Rice 안에 열린다. 제목에 RiceMonkey와 스크립트 이름을 표시한다. 아직 파일을 지정하지 않은 컴포넌트는 빈 문서로 열린다. 같은 메인 창이 이미 열려 있으면 그 창으로 이동한다.
- **목록 편집** — 메인 창에는 종류별 선언 목록 `Variables`, `Functions`, `Classes`, 직접 작성용 `Function Editor`와 `Class Editor`, 그리고 동작을 배치하는 정의부 `Start`와 `Every Frame`(C++ `Update`)이 있다. 편집 가능한 목록은 하단의 `+`로 해당 위치에 허용된 항목을 고르고 `−`로 선택한 항목을 제거한다. 선언 목록과 정의부는 한 줄 여백과 배경색으로 구분한다. 각 항목 제목 오른쪽의 세모는 접히면 `▲`, 펼치면 `▼`다.
- **함수·클래스 분리 창** — 함수 또는 클래스를 우클릭한 뒤 `Separate Window`를 선택하면 해당 항목의 편집 창 하나가 열린다. 같은 함수도 여러 창에 열 수 있고 각 창을 나란히 도킹하거나 탭으로 묶을 수 있다. **메인 창을 닫아도 분리 창과 그 창의 미반영 편집본은 유지된다.**

분리 창의 `Apply Changes`는 해당 항목의 편집 내용을 문서 초안에 반영한다. 같은 항목을 목록·다른 창·IDE·AI에서 수정하면 **가장 최근에 수정한 항목 내용**을 적용한다. 서로 다른 항목의 변경은 모두 유지한다. 오래된 창을 다시 열거나 문서를 저장한 시점은 그 항목을 실제로 수정한 시점과 구분한다.

### 1.1 Find Instances

변수 또는 함수를 우클릭해 `Find Instances`를 선택한다. 함수 메뉴에는 `Find Instances`와 `Separate Window`가 함께 있고, 변수에는 전자, 클래스에는 후자를 제공한다. Instance는 편집 문서에서 그 선언을 사용하는 **코드 위치**다. 같은 함수를 두 창에 열거나 게임 오브젝트를 두 개 실행해도 사용 위치 수는 늘지 않는다.

1. **현재 창이 보여주는 문서와 선택한 선언의 스코프가 겹치는 범위**에서 같은 선언의 사용 위치를 모은다. 현재 문서의 코드 순서로 보여주며, 이 창의 반영·미반영 편집을 따로 분류하지 않는다. 다른 창이나 프로젝트 파일로 검색을 넓히지 않는다.
2. `↑` 또는 `←`는 이전 결과, `↓` 또는 `→`는 다음 결과를 선택한다. 양 끝에서는 현재 위치에 머물며 순환하지 않는다. 접힌 항목을 펼쳐 현재 결과를 미리 보여준다. 안내 문구는 “Use the arrow keys to browse. Press Enter or click anywhere to go to the selected instance.”다.
3. `Enter`를 누르거나 화면 아무 곳을 클릭하면 탐색을 끝내고 **선택된 Instance로 커서를 이동**한다. 종료용 클릭이 배경의 삭제나 편집 버튼까지 실행하지 않게 처리한다. 결과가 없으면 “No instances found.”를 표시하고 기존 커서를 유지한다.

## 2. 저장·불러오기·컴파일

상단 툴바에는 `Save`, `Load`, `Open in C++`를 둔다. IDE나 AI가 C++ 파일을 저장하면 변경된 항목을 즉시 목록에 반영한다. **컴파일은 Rice에서 명시적으로 저장을 확정할 때만 실행하고 성공본은 다음 Play부터 적용한다(D3).** 현재 Play는 시작 당시의 성공본으로 실행한다.

| 조작 | 동작 |
|---|---|
| `Save → Save` | 현재 편집본을 컴파일하고 성공하면 원문과 성공본을 확정한다. 실패하면 편집본과 진단을 유지한다. IDE가 이미 디스크에 쓴 원문은 되돌리지 않으며 마지막으로 실행 가능한 성공본을 보존한다. |
| `Save → Save As...` | Windows 파일 대화상자에서 위치와 파일명을 지정하고 저장을 확정하면 같은 컴파일·저장 절차를 수행한다. 성공한 뒤 파일 연결과 창 제목을 갱신한다. 취소하면 기존 연결과 편집본을 유지한다. |
| `Save → Save as Preset` | 현재 편집본과 일치하는 컴파일 성공본의 C++ 텍스트를 프리셋으로 보관한다. 저장 이후 편집했다면 “Save this script before creating a preset.”을 표시한다. |
| `Load → Load File...` | 선택한 파일을 읽고 검증한 뒤 단일 파일 연결을 교체한다. 취소하거나 실패하면 기존 연결과 편집본을 유지한다. |
| `Load → Load Preset...` | 프리셋 불러오기는 C++ 텍스트를 복사하는 것과 같다. 원본과의 연결은 생기지 않는다. 현재 문맥에 연결되지 않은 외부 대상·정책은 빈칸으로 두고 영어 오류를 표시한다. 저장 전까지 채울 수 있으며, 필수 연결이 비어 있으면 저장 검증에서 위치를 알려준다. |
| `Open in C++` | 연결된 C++ 원문 파일을 `Settings → Script editor`에서 지정한 IDE로 연다. [기존 IDE 실행 기능](../../Platform/Windows/WindowsFileDialog.cpp) |

### 2.1 닫기 경고

저장하지 않은 변경이 있는 메인 창을 닫으면 다음 경고를 표시한다.

> You have unsaved changes. Close this window?
>
> **Save**　 **Don't Save**　 **Cancel**

| 선택 | 결과 |
|---|---|
| `Save` | 문서를 컴파일하고 저장한다. 성공하면 메인 창을 닫는다. 컴파일 또는 파일 저장에 실패하면 창과 편집본을 유지하고 원인을 표시한다. |
| `Don't Save` | 메인 문서의 미저장 변경을 버리고 메인 창을 닫는다. 분리 창에서 아직 `Apply Changes`로 반영하지 않은 내용은 해당 창에 유지한다. |
| `Cancel` | 닫기를 취소하고 현재 창과 편집 상태를 유지한다. |

메인 문서에 미저장 변경이 없으면 경고나 컴파일 없이 메인 창을 닫는다. 열린 분리 창은 계속 같은 문서와 항목을 가리킨다.

### 2.2 오류 표시

오류가 발생한 **변수·함수·클래스·스크립트의 제목**을 빨간색으로 표시한다. 예를 들어 클래스의 멤버 함수 안에서 지역 변수의 자료형 오류가 발생하면, 변수명과 자료형 버튼 글자, 함수 제목, 클래스 제목, 스크립트 창 제목을 빨간색으로 표시한다. Inspector의 해당 `Open RiceMonkey`도 빨간색으로 표시한다. 목록이 접혀 있어도 어느 항목을 펼쳐야 하는지 알 수 있어야 한다.

수정본에서 오류가 해소되면 해당 항목의 색을 복원한다. 같은 상위 항목 안에 다른 오류가 남아 있으면 그 상위 제목의 빨간색은 유지한다. 스크립트가 정상 실행되면 창 제목과 `Open RiceMonkey`도 원래 색으로 돌아온다.

## 3. 선언부

`Variables`, `Functions`, `Classes`는 현재 소유 범위의 선언을 종류별로 보여준다. `Function Editor`와 `Class Editor`에서는 기존처럼 함수와 클래스를 직접 만들고 본문을 편집한다. 각 작성부와 정의부가 같은 선언을 가리키므로 이름이나 반환형을 두 곳에서 다시 입력할 필요가 없다.

**정의부에서 선언하는 동작은 작성 위치로 이동하는 명령이다.** `Start`·`Update`·함수 본문에서 `New Function`, `Set Variable` 또는 `Add Variable`을 선택하면 즉시 해당 소유 범위의 작성부·선언부로 포커스를 이동한다. 입력은 그곳에서 완료하며, 정의부에는 선언 행이나 실행할 자리표시자가 남지 않는다. 이미 작성한 함수·클래스는 호출·생성하는 곳이 0개여도 보존한다.

| 선언 위치 | 보이는 범위와 수명 |
|---|---|
| `Start`, `Update`, 사용자 함수의 지역 선언 | 각 호출의 지역값이다. `Start`에서 만든 변수는 `Update`에서 보이지 않는다. 함수를 다시 호출하면 새로 초기화한다. 여러 프레임에 걸쳐 같은 호출을 재개할 때는 그 호출의 값을 유지한다. |
| 스크립트 변수 / 클래스 멤버 | 해당 스크립트 또는 클래스 인스턴스의 수명 동안 유지한다. `Start`와 `Update`가 공유할 값은 스크립트 변수로 선언한다. RiceCon을 통한 외부 데이터의 수명은 3.2절을 따른다. |
| 이름 | 선언 이름은 C++에서 유효한 식별자의 원문을 보존한다. 같은 스크립트에서는 스코프나 선언 종류가 달라도 동명 선언을 허용하지 않는다. 다른 후손 스크립트에서 같은 이름이 검색되면 소유 경로를 함께 표시한다. |

**선언 삭제와 미사용 함수 로그(Q3/D1).** 변수·함수·클래스 선언은 사용자가 직접 삭제한다. 예를 들어 `Call Function → ShowHealth(hp)`가 마지막 호출일 때 그 행을 삭제해도 `ShowHealth`의 선언·본문과 `hp`의 선언은 남는다.

에디터의 `Save` 검증에서 선언된 사용자 함수의 호출·참조와 엔진에 등록된 콜백을 확인한다. 프로젝트에서 사용처가 확인되지 않은 함수는 이름과 소스 위치를 담아 `Warning`으로 한 번씩 기록한다. 예: “No uses found for function 'ShowHealth'.” 지정된 진입점과 등록된 콜백은 사용처로 인정한다. 현재 창으로 제한된 `Find Instances`의 결과만으로 판정하지 않는다. 이 경고는 저장·컴파일 성공 여부에 영향을 주지 않는다.

### 3.1 변수와 후손 조회

변수 행은 **가시성 표시 → RiceCon 체크박스와 설정 세모 → 자료형 선택란 → 변수명 입력란 → 초기값** 순서다. 모든 변수는 `private`으로 선언하며 가시성은 읽기 전용으로 표시한다.

1. `Children`은 **컴포넌트가 부착된 오브젝트를 시작점으로 그 Scene 계층의 전체 후손**을 탐색한다. `GetHierarchyParent()` 관계를 따르며 접히거나 비활성인 후손도 포함한다. 현재 Scene 밖의 오브젝트는 제외한다. 같은 파일을 여러 곳에 붙여도 **Child 대상 연결은 컴포넌트별**로 저장한다. 최초 조회를 위해 `private`인 후손 변수도 읽기 후보에 표시한다. [Scene 계층 구현](../../Editor/HierarchyCache.h)
2. 변수를 선택하면 부모 함수의 편집본에 읽기 참조를 기록한다. 선택하거나 분리 창의 `Apply Changes`를 누른 시점에는 `private` 표시를 유지한다.
3. 해당 조회를 포함한 부모 스크립트가 **컴파일과 파일 저장에 모두 성공한 순간**, 후손 변수를 `protected`로 바꾸고 선언 행을 갱신한다. 저장 실패, 취소, `Don't Save`로는 승격하지 않는다. 문서를 다시 열어도 저장된 참조와 가시성을 복원한다.
4. 이번 버전에서 부모 함수는 후손 변수를 **읽기 전용**으로 조회한다. `protected`로 승격된 뒤에도 후손 변수에 대입하거나 값을 변경할 수 없다. Parent가 선택한 변수명을 초록색으로 표시하고 Parent의 선택을 우선한다. 선택된 변수에 오류가 있으면 제목의 빨간색을 우선한다.
5. 저장된 유효한 부모 참조가 하나라도 남으면 `protected`를 유지한다. 마지막 참조를 제거한 편집본이 저장되면 **변수는 그대로 두고 가시성을 `private`으로 되돌린다.** 부모가 삭제되거나 계층이 변경되어 유효 참조가 사라져도 같은 규칙을 적용한다.

가시성에 마우스를 올리면 `private`은 “Available only within this script.”, `protected`는 “Readable by an ancestor script function through a saved reference.”를 표시한다.

### 3.2 RiceCon

`RiceCon` 글자를 클릭하면 “RiceCon lets you change this variable through YouTube comments.”를 표시한다. 체크박스가 꺼져 있으면 옆 세모는 회색이고 클릭할 수 없다. 체크한 뒤 세모를 펼치면 작은 설정 창에 `scope`, `life`, `access`를 한 줄씩 표시한다. 각 줄의 단일 버튼을 누르면 값이 순환한다.

| 설정 | 값 | 버튼에 마우스를 올렸을 때 표시할 영어 안내 |
|---|---|---|
| `scope` | `build` / `global` | “Scoped to this build.” / “Shared across builds in the same storage domain.” |
| `life` | `game` / `slot` / `stored` | “Resets when the game session ends.” / “Persists for this game in its main broadcast slot.” / “Persists independently of the broadcast slot.” |
| `access` | `locked` / `policy` / `open` | “YouTube comments cannot change this variable.” / “Only users authorized by the YouTube policy can change this variable.” / “Anyone can overwrite this variable through YouTube comments.” |

기본값은 `build / game / locked`다. `global`에서는 `life`를 `stored`로 고정하고 회색으로 비활성화한다. `slot` 값은 주 방송 슬롯과 게임 종류에 연결되며 방송 종료 후에도 유지한다. `policy`의 권한 기준은 **추후 구현할 Rice의 YouTube 탭**에서 관리하며, 변수 편집기에는 적용할 정책의 참조를 보관한다. [Data Routing 명세](../../Data/DataRouting.md)

### 3.3 자료형과 초기값

자료형 버튼에는 현재 선택된 자료형을 표시한다. 버튼을 열면 상단에 검색창, 아래에 후보 목록이 나타난다. 검색어를 입력하면 이름에 입력 문자열이 포함된 후보만 보여 준다. 일치하는 후보가 없으면 `no result...`를 표시한다.

| 분류 | 선택 및 편집 방식 |
|---|---|
| `Basic` | `int`, `float`, `bool`, `vector 2`, `vector 3`. 변수 행 오른쪽에서 초기값을 입력하며 벡터는 성분별로 입력한다. `bool`은 텍스트 버튼으로 전환하고 기본값은 `true`다. |
| `Container → list` | `std::vector`에 대응한다. 초기값 영역 첫 줄에 원소 자료형 선택란과 `+ / −`를 두고 각 행에는 순서와 값을 표시한다. 원소는 이름 없이 `List[i]`로 접근한다. |
| `Container → dictionary` | `std::unordered_map`에 대응한다. 초기값 영역 첫 줄에 **Key 자료형 선택란과 Value 자료형 선택란을 각각 하나씩** 두고 `+ / −`를 표시한다. 각 행의 `Key / Value`는 각각 선택한 자료형으로 입력·검증한다. |
| `Classes → Here` | 현재 스크립트에서 선언한 클래스를 표시한다. |
| `Classes → Elsewhere...` | 클래스가 선언된 다른 스크립트 목록을 표시하고, 선택한 스크립트 안에서 클래스를 고른다. |
| `Children` | 전체 후손에서 참조할 수 있는 변수·함수·클래스를 표시한다. 변수에는 3.1절의 읽기 전용 및 저장 시 승격 규칙을 적용한다. |

### 3.4 함수·클래스 작성부

| 항목 | 구조 |
|---|---|
| `Function Editor` | `New Function`으로 즉시 이동하거나 직접 함수를 만든다. 첫째 줄은 `Scope`(`public / private`), `Return Type`, 함수명, 둘째 줄은 `Parameters`, 셋째 줄은 지역 선언과 실행 본문이다. 실행은 `Call Function`에서 요청하고 인수는 명시한다. |
| `Class Editor` | 클래스명, 멤버 선언 목록, 정의부를 둔다. 클래스마다 생성 시 동작과 소멸 시 동작을 개별 옵션(표시명 제안 `On Create`, `On Destroy`)으로 켜고 목록을 작성한다. 클래스 정의는 사용처가 없어도 유지한다. `New Class`가 만드는 대상은 해당 타입의 인스턴스다. |

## 4. 정의부 메뉴와 실행 규칙

메뉴에서 **선언 작성**, **인스턴스 생성**, **실행할 동작**을 구분한다. `New Function`과 `Set Variable`은 선택 직후 각각 작성부와 선언부로 이동한다. 정의부에 남는 실행 행은 위에서 아래로 실행하며 분기·반복 본문도 같은 목록을 사용한다.

| 항목 | 화면 및 동작 |
|---|---|
| `New Class` | 기존 타입을 고른 뒤 `Enemy (set name)`에서 이름을 입력한다. 이름과 타입은 소유 범위의 선언부에 등록하고 정의부에는 생성 행을 둔다. 행을 실행할 때마다 인스턴스를 만들고 같은 자리에 기존 값이 있으면 먼저 소멸시킨다. 지역 인스턴스는 호출이 끝날 때, 멤버는 소유 인스턴스가 소멸할 때 한 번씩 정리한다. 편집이나 프리셋 복사는 생성·소멸 콜백을 실행하지 않는다(D6). |
| `Change Variable` | `change (add parameter) into (add value)`. 대입 대상은 `Defined`의 현재 범위 변수 또는 `Engine`의 `Game Speed`다. `Game Speed`에 대입한 배율은 다음 프레임부터 게임 전체의 시간 계산에 적용한다. 없는 이름은 빨간색으로 표시하고 대입을 확정할 수 없다. `Add Variable`을 선택하면 곧바로 해당 선언부로 이동한다. 후손 변수는 값 쪽에서만 사용한다. |
| `Call Function` | 선언된 함수를 선택하고 매개변수에 들어갈 인수를 명시한다. 함수 호출은 독립된 실행 행으로도, 반환값이 필요한 식의 일부로도 사용할 수 있다. 지역 함수에 필요한 외부 값도 명시적 인수로 전달한다. |
| `Activate` | `Set (add object)`와 `Active / Inactive` 체크박스를 둔다. 대상은 `This → Object / Component` 또는 `Child → [descendant] → Object / Component`다. 비활성 대상을 포함한 전체 후손을 찾고 컴포넌트 대상은 해당 컴포넌트까지 선택한다. 저장 후 대상이 사라지면 해당 동작을 건너뛰고 영어 Error 로그를 남긴 뒤 다음 행으로 진행한다. 반대로 자기 자신을 비활성화하면 그 자리에서 현재 호출을 끝낸다. |
| `Move` | `Move (value) to (x) (y) (z) per (unit)`. 값과 월드 좌표계의 방향 성분을 직접 입력하고 단위를 고른다. 값이 있으면 방향 벡터를 정규화한 뒤 입력값을 곱한다. 음수는 반대 방향이며, 0은 그 행의 이동량이 0임을 뜻한다. 값이 비면 (x, y, z) 자체가 단위당 변위다. `second`는 현재 프레임의 실제 경과 초, `game second`는 게임 시간 배율을 적용한 경과 초를 변위에 곱한다. `frame`은 행을 실행할 때마다 해당 변위만큼 한 번 이동한다. |
| `Loop` | 첫 줄은 `loop (set Scope)`다. Scope가 비면 `while (true)`, List를 등록하면 해당 List의 모든 원소를 순서대로 한 번씩 순회하는 C++ 범위 기반 반복이다. 일반 3절 `for`와 `do-while`은 목록에서 제공하지 않는다. 별도 종료 조건 입력란은 없다. 중도 탈출은 `End → Loop`로 하고 List는 마지막 원소 뒤에 자연 종료한다. |
| `Wait` | 정의부의 `+ → Wait`로 `Wait (seconds)` 실행 행을 추가한다. 지정한 게임 시간 동안 현재 호출을 보류하고 만료 시 다음 행에서 이어간다. 입력과 시간 계산은 4.3절을 따른다. |
| `Condition` | `if (set condition)` 아래에 결과 코드 목록을 둔다. `+`의 `else if / else / and / or` 중 `else if`는 조건과 결과, `else`는 결과만 가진다. `and / or`는 선택한 조건을 한 줄 연장한다. 분기 순서를 바꿀 수 있고 `else`는 마지막에 한 번만 둔다. |
| `End → Function` | 반환형이 없는 함수와 `Start / Update`에서는 `End Function`만 표시한다. 반환형이 있으면 `End Function with (set Output)`에서 값을 지정한다. 중첩된 분기·반복 안에서도 현재 함수를 끝낸다. |
| `End → Loop` | `End Loop`는 가장 안쪽의 현재 반복만 끝내고 반복 다음 행으로 이동한다. 중첩 반복의 바깥쪽과 호출한 함수는 계속 실행한다. |

### 4.1 값과 조건 입력

- **식.** `Change Variable → Expression`은 다음 줄 텍스트박스에서 조건식, 산술식, 함수 호출을 모두 허용한다. `int`와 `float`는 자동 변환한다. C++ 변환을 따르면 `3.9 → 3`과 `−3.9 → −3`이다. 범위를 벗어나거나 유한하지 않은 값을 정수로 변환하려 할 때는 변환 전에 영어 진단을 내는 것을 제안한다. [C++ 실수·정수 변환 규칙](https://eel.is/c++draft/conv.fpint)
- **백틱.** 텍스트박스에서 백틱(U+0060)을 입력하면 바로 아래에 지역 변수·멤버·후손 검색이 열린다. 동명이면 `Player/LeftArm/health`처럼 소유 경로를 함께 표시한다. 선택한 변수가 삭제되면 참조한 위치를 빨간 오류로 남겨 사용자가 대상을 다시 고를 수 있게 한다. 안내 문구는 “Type a backtick to search for a variable.”다.
- **조건 후보.** 참·거짓 변수, 타입에 맞는 두 값 비교, 오브젝트의 활성 여부, 함수 반환값, `Physics`를 모두 제공한다. `and / or`는 **표시된 행의 순서**로 평가하고 선택한 괄호 그룹을 먼저 묶는다. 예를 들어 목록의 `A or B and C`는 `(A or B) and C`다. C++로 옮길 때도 괄호를 명시해 같은 결과와 단락 평가를 유지한다. 처음 참이 된 분기의 결과 목록만 실행한다.
- **물리 조건(D5).** 첫 줄에서 `Physics → Collision / Overlap / Overlap End` 중 접촉 단계를 고른다. **그 아래 줄에 별도의 조건식 입력란**을 둔다. 접촉마다 그 식을 평가해 하나라도 일치하면 참이다. 빈 식은 해당 단계의 모든 접촉과 일치한다. 예를 들어 `Collision` 아래의 식에 접촉 상대의 `Is Ground`를 넣으면 기본 Ground에 처음 닿을 때만 결과 목록을 실행한다. 일반 콜라이더와 트리거에도 같은 방식을 사용한다.
- **접촉 수명.** 처음 닿으면 `Collision`과 `Overlap`이 함께 참이고 접촉을 유지하면 `Overlap`, 처음 떨어지면 `Overlap End`가 한 번 참이다. 같은 Update의 여러 조건 행에서 같은 접촉을 읽을 수 있다. 물리가 스크립트 Update 뒤에 실행되므로 두 Update 사이의 시작·종료 이력과 최종 접촉 상태를 보관한다. 기본 Ground는 현재 엔진에서 바닥 보정으로 처리하므로, 오브젝트별 Ground 접촉을 별도로 추적해 같은 조건식에 제공한다. 바닥에 가만히 서 있는 동안에는 접촉이 유지되고 매 프레임 새 충돌이 발생하지 않아야 한다. [물리 접촉 처리](../../Scene/Gameplay.h) · [프레임 실행 순서](../../Project/Workspace.h)

### 4.2 프레임 간 호출 재개(D4)

**현재 엔진은 일반 스크립트의 반복문을 자동 재개하지 않는다.** `GameObject::Update`가 활성 컴포넌트의 동기 `Start()`·`Update(float)`를 직접 호출한다. 방송용 `CycleScheduler`는 작업이 스스로 반환한 `ActionTask`를 폴링한다. 임의의 C++ 호출에서 루프 위치와 지역 변수를 꺼내 다음 틱에 돌려놓는 기능은 제공하지 않는다. [씬 스크립트 실행](../../Scene/Scene.h) · [방송 작업 계약](../../Streaming/CycleScheduler.h)

**요구 동작과 구현 제안.** 프레임 예산을 다 쓰면 호출을 보류하고 다음 프레임에 같은 호출을 이어간다. 예산 도달은 정상 동작이다. 예를 들어 `[A, B, C]`에 대해 설명용 한도를 원소 2개로 잡으면 첫 프레임에 A·B, 다음 프레임에 C를 처리한다. A·B에서 이미 실행한 대입이나 함수 호출을 반복하면 안 된다.

컴포넌트별 프레임 예산은 중첩 호출과 공유한다. List는 순회 시작 시 원소 값을 복사해 끝까지 그 순서로 방문한다. `Start`가 완료된 뒤에 `Update`를 시작하고, 미완료 `Update`가 있으면 새 호출보다 먼저 재개한다. 함수가 보류되면 호출자도 기다린다. 외부에서 비활성화하면 실행을 일시정지하고, 자기 비활성화는 현재 호출을 끝낸다. Stop·파괴는 보류된 호출을 취소한다. 클래스의 `On Create / On Destroy`는 같은 호출에서 완료해야 한다.

구현 시 다음 실행 위치, 호출별 지역값·인수, 중첩 루프·호출 위치, List 사본과 순회 인덱스를 보관한다. 표준 C++20 코루틴과 프레임별 재개 처리를 조합하거나 같은 정보를 가진 C++ 실행 상태를 생성할 수 있다. 양보 지점은 구조화된 루프와 대기 행에 둔다. [프로젝트 C++ 설정](../../CMakeLists.txt) · [C++ 코루틴의 중단과 복귀](https://eel.is/c++draft/expr.await)

### 4.3 Wait의 입력과 시간

시간 단위와 0초 동작은 다음을 기본값으로 삼는다.

- `Wait (seconds)`는 초 단위이며 새 행의 기본값은 `1.0`이다. 숫자, 숫자형 변수 또는 식을 입력할 수 있다. 행에 진입할 때 한 번만 평가해 유한한 0 이상의 값인지 검증한다. 유효하지 않은 입력은 해당 행에 “Wait duration must be a finite, non-negative number.”로 표시한다.
- 대기 시작 다음 활성 Play 틱부터 해당 스크립트에 전달된 게임 시간 델타를 한 번씩 누적한다. 양수 대기는 지정 시간에 도달한 첫 틱에 다음 행을 한 번 실행한다. `Wait(0)`은 다음 활성 Play 틱까지 한 번 양보한다. Pause나 외부 비활성화 동안은 잔여 시간을 유지하고, 시간 배율이 0이면 양수 대기는 진행되지 않는다. [게임 시간 계산](../../Core/Source/Time.cpp) · [Play 틱](../../Project/Workspace.h)
- 보류된 호출의 지역값과 호출자를 유지하며 다른 컴포넌트의 업데이트와 렌더링은 계속된다. `Start`에서 기다리면 해당 컴포넌트의 첫 `Update`도 기다린다. Stop·파괴 후에는 다음 행을 실행하지 않는다. 같은 호출에서 완료해야 하는 생성·소멸 콜백에서는 직접 `Wait`하거나 대기하는 함수를 호출하는 경로를 저장 검증에서 알려준다.

## 5. C++ 원문·IDE·AI의 연결

### 5.1 C++ 단일 원본과 항목 식별(Q20/D2)

IDE·AI·목록은 **같은 C++ 원본 파일**을 사용한다. 짧은 선택적 ID 주석으로 선언과 행을 식별하고, 주석이 없는 항목은 C++ 구문을 읽어 복원한다. 목록으로 표현할 수 없는 유효한 C++는 원문을 보존한 `Custom Code` 행으로 표시한다. 식별이 모호한 경우에도 최신 원문을 보존한다. 예를 들어 AI가 `score += 1;`을 `score += 5;`로 수정하면 같은 행에 새 값이 표시되고 그 위에 주석을 삽입해도 기존 진단과 커서는 같은 항목을 가리킨다.

**확정된 동기화 단위는 항목이다.** 예를 들어 AI가 대입값을 수정하고 사용자가 다른 조건 행을 수정하면 양쪽 변경을 보존한다. 같은 대입 행을 양쪽이 바꾸면 마지막 변경을 적용한다. 구현 제안은 원문 변경 전후의 항목과 현재 창의 편집본을 비교해 변경된 항목에만 순서를 부여하는 것이다. 파일 전체의 수정 시각만으로 모든 행을 덮어쓰지 않는다. 외부 텍스트 붙여넣기로 ID가 중복되면 복사한 항목에는 새 ID를 부여한다. 구문이 깨져 행을 식별할 수 없으면 최신 원문과 영어 진단을 보존하고, 과거 목록을 파일 위에 다시 쓰지 않는다.

### 5.2 주요 구현 객체

| 객체 | 보유 상태와 책임 |
|---|---|
| `ScriptComponent` | 생성 유형, 활성 상태, 연결된 C++ 파일 하나, 소유 Scene, 컴포넌트별 Child 대상 연결을 보관한다. 스크립트 인스턴스의 멤버·상태·전략과 프레임 간 보류된 호출을 소유한다. |
| `ScriptDocument` | 원문, 소유 범위, 선언과 코드 위치, 작성부 및 목록의 현재 편집 상태를 관리한다. 목록 편집은 해당 원문 구간에 반영하고 외부 수정은 해당 항목에 다시 반영한다. |
| `DeclarationList`·`ScriptSymbolIndex` | 지역·멤버·스크립트 선언, 스크립트 전체 이름 중복, 사용 위치와 컴포넌트별 후손 읽기 참조를 추적한다. Find의 현재 창 필터와 저장된 부모 참조에 따른 가시성 판정을 구분한다. |
| `ScriptEditorSession` | 창·스코프, 미반영 편집, 항목별 변경 순서, 현재 탐색 결과와 커서를 관리한다. 분리 창의 독립 수명, 양 끝에서 멈추는 탐색, 선언부로 즉시 이동하는 동작을 담당한다. |
| `ScriptCompileService`·`ScriptStorage` | 명시적 저장 시 C++ 검증·컴파일 진단을 목록 행에 연결하고 미사용 함수 경고를 기록한다. 마지막 성공본, 다음 Play에 적용할 버전, C++ 텍스트 프리셋과 컴포넌트별 바인딩을 보존한다. |
| `ScriptExecutionFrame` (제안) | 수행 중인 호출의 실행 위치, 지역값, 하위 호출·순회 상태, `Wait` 잔여 시간과 대기 시작 틱을 보관한다. 루프 예산이나 대기 만료에 맞춰 같은 호출을 재개하고, 종료·취소·파괴 시 자원과 클래스 수명을 정리한다. |

Scene 계층의 `protected` 읽기는 C++ 상속 없이 검증된 대상 접근으로 구현한다. 지역 함수는 바깥 값을 명시적으로 전달하는 C++ 보조 함수 또는 람다로 표현할 수 있다. [C++ 함수 정의 범위](https://eel.is/c++draft/dcl.fct.def.general)

## 6. 빌트인 상태와 전략

- **상태는 첫 구현 대상이다.** `Set → State`와 `Change → State`를 별도 항목으로 제공한다. 상태는 인스턴스별 현재 값과 `On Enter / On Update / On Exit` 목록을 갖는다. 전환은 요청 순서대로 **즉시 모두** 적용한다. 같은 프레임에 `Patrol → Chase → Attack`이면 `Exit Patrol → Enter Chase → Exit Chase → Enter Attack`이 실행된다. 상태 콜백에서 다시 전환을 요청하는 경우도 프레임 끝의 한 건으로 합치지 않는다.
- **상태 재진입(D7).** 현재 상태를 다시 지정하면 그대로 유지하고 Exit·Enter를 재실행하지 않는다. 전환 콜백이 같은 경로를 반복해 무한 전환이 의심되면 “Possible state transition cycle: A → B → A.”처럼 경로가 담긴 Warning을 즉시 기록한다. **경고 후에도 전환을 계속 실행한다.** 경고를 이유로 전환을 중단·누락하거나 다음 프레임으로 미루지 않는다. 동일 연쇄의 중복 로그는 합칠 수 있다.
- **전략은 호환되는 입력·반환형을 가진 행동으로 교체할 수 있다.** 교체할 때 이전 전략의 내부 상태를 초기화한다. 나중에 원래 전략으로 돌아와도 옛 상태가 이어지지 않는다. 사용자에게는 이름과 명시적 입력을 보여주고 구현은 값과 행동을 조합한다. 첫 기능 우선순위는 상태다.
- 점수 계산·이동·대상 선택을 예로 든 [전략 패턴 구현 계획과 인수 기준](StrategyPatterns.md)에서 슬롯 작성, 교체 중인 호출의 수명, C++ 원문과의 연동을 정한다.
- 기존 명령·이벤트 패턴 제안은 이후 확장 후보로 둔다. 프리셋을 이용해 행동을 복사할 수 있으며 복사할 때 외부 Scene 대상이 따라가지 않는다.

## 7. 구현 순서와 인수 기준

| 단계 | 확인할 결과 |
|---|---|
| 1. 선언·작성부 | `Start`의 `Set Variable`과 함수 본문의 `New Function` 모두 올바른 선언 위치로 이동하고 실행 행 수는 그대로다. `Start` 지역 변수는 `Update`에서 선택할 수 없다. 마지막 사용 행을 삭제하고 저장·재개방해도 변수·함수·클래스 선언은 보존된다. 미사용 함수의 이름과 위치가 경고로 남고, 호출을 추가한 뒤 저장하면 새 경고가 발생하지 않는다. |
| 2. 목록·검색·연결 | 미선언 대입 대상은 빨간색이고 `Add Variable`로 이동한다. 같은 파일을 쓰는 두 오브젝트의 `Child` 바인딩은 독립적이다. 숨김·비활성 후손, 마지막 부모 참조 삭제 후 `private` 복귀, 끊어진 백틱 참조, 현재 창에서 양 끝에 멈추는 탐색을 확인한다. |
| 3. 기본 C++ 실행 | 스크립트 멤버 `score`가 `0`에서 시작해 `Update`에서 1씩 증가한다. 두 번째 업데이트에서 자식 램프가 켜진다. 대상 삭제 시 Error 로그 뒤 다음 행이 실행되고 자기 비활성화 시에는 현재 호출이 끝난다. 함수의 인수·반환과 괄호를 바꾼 논리식도 확인한다. |
| 4. 호출 재개·클래스 수명 | 빈 List는 건너뛰고, 세 원소를 두 프레임에 나눠 순회하는 도중 원본을 수정해도 최초 원소를 한 번씩 방문한다. 중첩 호출은 하나의 프레임 예산을 사용한다. 반복에서 `New Class`를 두 번 실행하면 이전 인스턴스의 소멸이 새 생성보다 앞서고, 마지막 인스턴스는 소유 수명이 끝날 때 정확히 한 번 소멸한다. |
| 5. Wait | `Start`의 `Wait(0)` 다음 행은 다음 활성 틱에 정확히 한 번 실행되고 첫 `Update`는 그 뒤에 시작한다. 중첩 함수의 `Wait(1)`은 다른 컴포넌트의 진행을 허용한다. 게임 시간 0.4초 후 Pause 또는 외부 비활성화를 하면 재개 시 0.6초가 남는다. Stop·파괴 후에는 대기 다음 행이 실행되지 않는다. |
| 6. 물리·상태 | 기본 Ground 접촉을 아래 조건식의 `Is Ground`로 걸러낸다. 착지 때 시작·유지, 정지 중 유지, 이탈 때 종료 한 번을 확인한다. 일반 충돌과 트리거도 같은 입력 구조를 쓴다. 상태 전환은 같은 프레임에 요청된 순서를 지킨다. 순환 의심 경고가 난 뒤에도 동작을 관찰할 수 있도록 자체 종료 조건이 있는 반복 전환 예제로 경고 뒤의 마지막 전환까지 실행되는지 확인한다. 전략 교체 후에는 이전 내부 상태가 초기화된다. |
| 7. 원문 왕복·호환 | IDE·AI의 파일 변경은 즉시 목록에 반영되고 컴파일 횟수는 명시적 저장에서만 증가한다. 주석이 없는 코드와 `Custom Code`가 보존되며 성공본은 다음 Play에 적용된다. 프리셋 독립 복사, 한글 경로, 프리팹·Undo/Redo, RiceCon과 Dictionary 설정의 복원도 검증한다. |
