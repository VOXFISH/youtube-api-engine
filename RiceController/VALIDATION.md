# Rice Controller 구현 및 검증

검증일: 2026-11-16, Asia/Seoul

## 구현 결과

`RiceController.exe`에서 항목 추가·이름 변경·제거·경로 선택·설정 저장과 인스턴스별 실행·일시정지·재개·종료·숨김·전체화면 제어를 구현했다. 요청한 아이콘, 가장 작은 빈 번호의 `빌드 N` 이름, 추가·편집 취소, 탐색기 위치 열기, 빈 설정 창의 최대화·최소화·닫기, 상단 전체 설정을 포함한다.

송출, YouTube/API 연결, 변수 조작과 전체 설정의 실제 처리는 요청대로 더미다. 전체화면은 모니터의 디스플레이 모드를 바꾸지 않는 테두리 없는 창이며 Esc로 복원한다.

엔진 내부에 실행 스레드를 추가하지 않았다. 플레이어의 기존 메인 루프에서 로컬 IPC 명령을 받아 기존 `Workspace::Pause/Resume()` 및 종료·창 모드 기능에 연결했다. 엔진 측 변경은 창 생성 옵션, 한글 명령줄 경로, 제어 연결, 실행별 진단 경로와 Export의 제어 표시 파일 복사다.

컨트롤러 소스·공유 프로토콜·테스트는 `RiceController/`에, 플레이어 제어 연결은 `Sandbox/Source/PlayerControl.h`에 추가했다. 실행 프로그램과 `RicePlayer.control`의 현재 배포 위치는 저장소 최상단이다. 발표용 정리 과정에서 예전 `TestBuild` 보존본은 `Build/legacy-backup/TestBuild`로 옮겼으며, 아래 수치와 결과는 정리 이전에 완료한 검증 기록이다.

## 빌드와 자동 검사

환경: Windows x64 (빌드 26200), 논리 프로세서 32개, NVIDIA GeForce RTX 4060 Ti, Visual Studio 2026 Release.

```powershell
cmake --build Build/logging --config Release --parallel 4
ctest --test-dir Build/logging -C Release --output-on-failure
cmake --install Build/logging --config Release --prefix .
```

Release 빌드 성공. 기존 18개와 신규 3개를 합한 **CTest 21/21 통과**, 실패 0개, 총 13.87초. 로컬 파이프 검사는 일반 데스크톱 권한에서 수행했다. 제한된 Low Integrity 테스트 환경에서는 같은 사용자 전용 파이프 접근이 거부되어, 파이프 권한을 넓히지 않고 정상 데스크톱 환경에서 검사했다.

| 검사 | 확인 내용 | 결과 |
|---|---|---|
| 기존 18개 회귀 검사 | 엔진·렌더링·프로젝트·에디터·진단 | 모두 통과 |
| ControllerModel | 빈 번호 이름, 한글 이름·경로, 설정 저장·교체·재읽기, 손상 원본 보존, 인수 인코딩, JSON 및 실제 양방향 파이프 | 통과 |
| ControllerWindow | 숨김 컨트롤러의 ImGui 초기화·120프레임 렌더링·정상 종료 | 통과 |
| ControllerIntegration | 실제 다중 플레이어 제어·창 모드·독립 종료·실패 처리·Job 정리 | 40개 확인 항목 통과 |

초기 통합에서 `PIPE_NOWAIT`의 `ConnectNamedPipe` 최초 성공 반환을 실제 연결 완료로 오인하는 문제를 수정하고, 리스닝 상태와 실제 연결을 구분하는 파이프 회귀 검사를 추가했다.

전체 검사 후 UI의 접근 불가 경로 처리와 이전 빌드의 창 모드 선택을 보완했다. 최종 컨트롤러를 재빌드하여 `ControllerWindow`를 다시 통과했고, 잘못된 경로가 등록된 목록으로도 120프레임 실행·정상 종료를 확인했다. 백엔드와 플레이어 코드는 전체 검사 이후 변경하지 않았다.

## 실제 프로세스 제어

통합 검사는 별도 런타임 복사본과 한글·공백이 있는 프로젝트 경로를 사용했다. 음원 장치에 의존하지 않도록 `--silent-audio`를 사용했다.

- 동일 실행 파일·프로젝트로 3개를 처음부터 숨겨 실행하고 고유 PID·숨겨진 HWND·게임 프레임 증가 확인.
- 재생 중복 요청 시 기존 PID 유지. 한 플레이어 일시정지 시 게임 프레임 정지, 렌더 프레임·IPC 응답 유지, 다른 플레이어 진행 확인.
- 재개 시 같은 PID로 진행. 전체화면에서 창 표시·모니터와 일치하는 크기·테두리 제거·PID 유지, 다시 숨김 전환 확인.
- 중간 인스턴스 정상 종료 후 다른 인스턴스 진행. 일시정지 중 종료와 정지 후 새 PID로 재시작 확인.
- 표시 파일이 없는 빌드의 제한 모드·미지원 명령 거절·정상 종료 확인.
- 잘못된 실행 경로, 테스트 전용 비정상 종료, 컨트롤러 Job 정리와 프로젝트 파일 내용 불변 확인.

기본 동시 실행 PID는 `23284`, `9528`, `26092`였으며 정상 종료 검사의 종료 코드는 모두 0이었다. 비정상 종료 검사는 테스트가 만든 별도 프로세스만 대상으로 했다.

통합 검사 원시 파일은 임시 산출물 정리 시 제거했다. 다시 실행하면 `Build/logging/TestData/ControllerIntegration` 아래에 새 결과가 생성된다.

설치한 플레이어도 `scripts/Verify-MultiInstance.ps1`로 다시 검사했다. 3개 smoke의 120프레임 완료, 별도 3개 일반 실행의 독립 종료, 프로젝트 SHA256 불변을 통과했다. 이 검사는 기본 FMOD 출력 초기화로 실행했다. 현재 스크립트의 기본 실행 위치는 저장소 최상단, 프로젝트는 `Presentation/Grass1000`이다.

다중 실행 검사 원시 파일도 정리했다. 다시 실행한 결과는 `Build/multi-instance`에 기록한다.

## 실제 UI 확인

사용자 기본 목록과 분리한 `Build/controller-ui/controller.json`으로 실행하고 Windows UI 자동화로 확인했다.

- 한글 목록·헤더·툴팁·요청한 아이콘 표시.
- `빌드 1`, `빌드 3`이 있을 때 `빌드 2` 제안, 추가 취소 후 기존 2개 유지.
- 재생 버튼으로 숨김 실행, 실행 중·PID·숨김 표시, 일시정지 버튼으로 같은 PID의 상태 전환.
- 렌치로 빈 설정 창 열기와 최소화·최대화·닫기. 플레이어 일시정지 상태 유지.
- 빨간 송출 버튼의 미구현 안내, 상단 3개 메뉴와 방송 설정의 준비 중 창.
- 컨트롤러 닫기의 확인 창, 모두 정지 후 종료, 컨트롤러와 플레이어 종료 완료.

테스트 항목은 사용자 기본 목록에 저장하지 않았으며 테스트 프로세스는 모두 종료했다.

## 확인 범위

완성된 프로젝트와 `.meta`가 갖춰진 플레이어의 동시 재생을 검증했다. 같은 프로젝트의 동시 편집·저장, 누락된 메타데이터의 동시 생성, 사용자 스크립트가 공유 파일에 쓰는 경우의 충돌은 별도 범위다. 컨트롤러로 실행한 플레이어의 함수 진단 경로는 실행 ID별로 분리했다.

장시간 안정성·최대 인스턴스 수·코어별 배치·선형 성능 확장·실제 방송 성능은 측정하지 않았다. 샘플에 재생 음원이 없어 실제 소리 혼합 출력은 이번 다중 프로세스 검사에서 확인하지 않았다. 원시 기록과 임시 설정은 Git에서 제외된 `Build/`에 있다.
