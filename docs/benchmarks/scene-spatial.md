# 장면 BVH·월드 행렬·경계 캐시

측정일: 2026-11-16. 아래 분석과 측정 요약은 보존하고, 발표 폴더 정리 과정에서 원시 CSV는 제거했다. 같은 측정은 `Tests/Benchmarks/SceneSpatialBenchmark.cpp`로 재현할 수 있다.

## 구현

- `Engine/Scene/SpatialBVH.h`: 기존 MeshIntersection의 최장 축 중앙 분할을 공통 BVH로 추출했다. 리프당 최대 8개, 원본 인덱스 유지, AABB 겹침/시야체/광선 질의, refit을 지원한다. 메시 광선 검사는 가까운 자식부터 방문한다.
- `Engine/Scene/Scene.h`: 실제 부모 행렬·로컬 transform·기하 기반 pivot을 비교해 월드 행렬을 재사용한다. 공개 필드 직접 변경, 부모·그룹·anchor 변경을 감지하기 위해 의존성 확인은 매 호출 유지한다. 전체 계층 조회가 O(1)이 되는 캐시는 아니다.
- `Engine/Scene/Components.h`: 커스텀 메시 로컬 경계와 BoxCollider 월드 경계를 캐싱한다. 커스텀 메시의 직접 정점 변경/대입 후에는 기존 GPU 메시·교차검사 캐시와 마찬가지로 `custom.Touch()`가 필요하다. 초기 빈 메시를 기본 도형으로 바꾸는 경로는 데이터 주소/개수 변경도 감지한다.
- `Engine/Scene/SceneSpatial.h`: 활성 렌더러의 월드 행렬과 경계를 스냅샷으로 준비한다. 객체 목록 변경 시 build, 경계 변경 시 refit, 정적 장면에서는 경계와 트리를 재사용한다. 연속 refit 64회 뒤 다음 변경에는 재구축한다.
- 큐브맵을 실제 갱신할 때만 스냅샷을 준비하고, 모든 프로브의 6면에 공유한다. 면별 시야체 질의 결과는 원래 장면 순서로 정렬해 투명도/제출 순서를 유지한다. 캡처 그리기는 스냅샷의 월드 행렬도 재사용한다. 메인 카메라 가시 목록으로 반사 물체를 제한하지 않는다. 기존 컬러 큐브맵 갱신 정책은 유지한다.
- `CollisionSystem`: 경계를 한 번 모아 BVH로 겹치는 쌍을 찾는다. 이 간단한 정적 검사 API는 호출마다 트리를 만들며 그 비용도 측정에 포함한다.
- `PhysicsSystem`: 지속되는 충돌 BVH를 재사용한다. 기존 `(i,j)` 순서를 유지하고, 위치 보정 후 부모/그룹에 종속된 물체까지 경계를 갱신해 새 충돌을 찾는다. 보정이 많으면 객체 수에 비례한 갱신 예산 뒤 남은 쌍을 캐시된 순차 검사로 처리한다. 밀집 64개 사례에서는 전역 갱신을 3회로 제한한다. 예산은 경험적 휴리스틱이며 모든 장면의 성능 향상을 보장하지 않는다.

렌더링/충돌 BVH는 물체 집합과 갱신 시점이 달라 각각 유지하되 공통 BVH 구현과 월드 행렬 캐시를 사용한다. 이번 변경은 CPU 공간 검색에 해당하며 GPU 반사 셰이더의 삼각형 선형 탐색이나 섀도맵은 변경하지 않는다.

## 재현

이미 구성된 Windows Release 빌드 디렉터리에서:

```powershell
cmake --build Build/logging --config Release --parallel 4
cmake --build Build/logging --config Release --target RiceSceneSpatialBenchmark --parallel 4
ctest --test-dir Build/logging -C Release --output-on-failure
New-Item -ItemType Directory -Path Build/benchmarks -Force | Out-Null
& ./Build/logging/bin/Release/RiceSceneSpatialBenchmark.exe | Tee-Object Build/benchmarks/scene-spatial-results.csv
```

벤치마크는 CTest 시간 제한 테스트가 아니라 수동 실행 대상이다. 실행 중 다른 빌드나 테스트를 병행하지 않았다.

## 조건과 결과

- NVIDIA GeForce RTX 4060 Ti, OpenGL 3.3.0 / NVIDIA 610.88. CPU 식별 문자열은 원본에 기록했다.
- 같은 Release 실행 파일에서 `legacy`(캐시/BVH 해제), `cache_only`, `cache_bvh`를 전환했다. 과거 바이너리와의 비교는 아니며 공통 계측/호출 구조는 세 모드 모두 포함한다.
- 세 번 순서를 교대하고 중앙값을 사용했다. 렌더링은 실행당 준비 3회 + 측정 10회, 충돌 검사는 준비 1회 + 측정 4회다. 물리 스텝은 새 장면의 첫 스텝 3회 중앙값으로 트리 최초 구축 비용을 포함한다.
- 렌더링은 메인 뷰 64×64, 큐브맵 각 면 64×64, 물체 1,000개와 반사 수신체 1개다. 물체 배치는 결정적이며 정적/이동 조건을 모두 측정했다.
- CPU 시간에는 이동·캐시 확인·BVH 유지·렌더 제출이 포함된다. 아래 큐브맵 시간은 `glFinish`까지 기다린 전체 완료 시간이며, 순수 GPU 시간이나 에디터 FPS가 아니다.

| 작업 | 기존 경로 (ms) | 캐시만 (ms) | 캐시 + BVH (ms) |
|---|---:|---:|---:|
| 큐브맵 1,000개, 정적 | 23.4711 | 22.6378 | 7.4756 |
| 큐브맵 1,000개, 이동 | 22.9008 | 22.0786 | 7.4127 |
| 충돌 검사 1,000개, 정적 | 123.5154 | 73.6445 | 0.5427 |
| 충돌 검사 1,000개, 이동 | 119.9956 | 70.8933 | 0.6316 |
| 충돌 검사 64개, 밀집 | 0.4811 | 0.2946 | 0.0577 |
| 물리 스텝 1,000개, 희소 | 146.6090 | 96.3921 | 0.7068 |
| 물리 스텝 64개, 밀집 | 0.9218 | 0.8444 | 0.8901 |

정적 큐브맵은 약 3.14배 빨라졌고 캡처 객체 제출은 6,000회에서 1,036회로 감소했다. 이동 조건은 1,035회다. 정적 조건의 반복 측정에서는 경계 재계산과 트리 갱신이 0회였고, 이동 조건에서는 1,000개 경계 갱신과 1회 트리 갱신이 있었다.

정적 1,000개 충돌 검사는 기존 499,500쌍 비교 대신 BVH가 반환한 겹침 쌍 289개를 처리했다. 이 수치는 BVH 내부 노드/리프의 경계 검사까지 합친 총 검사 횟수가 아니다. 속도 향상에는 기존의 쌍마다 반복되던 행렬·경계 계산을 줄인 효과도 포함된다.

밀집 물리에서는 캐시만 사용한 경로가 더 빠르다. 첫 구현은 보정마다 전체 refit을 해 6.4ms까지 느려졌으나, 예산 초과 시 순차 검사로 전환하여 최종 결과는 약 0.89ms다. 따라서 큰 희소 장면의 개선율을 밀집 장면이나 전체 게임 FPS로 일반화하면 안 된다.

## 검증

`SceneSpatialTests`는 무작위 BVH 질의와 refit, 직접 transform/부모/그룹/anchor 변경, 커스텀 메시 수정, 활성 상태/삭제/장면 교체, 정적 캐시 재사용, 충돌 개수/플래그 동등성을 검사한다. 12개 반사 이미지와 최초 직접 캡처를 기존 방식과 픽셀 단위로 비교한다.

`SpatialPhysicsTests`는 위치·속도·충돌/트리거 이벤트, 보정 후 새로 생기는 접촉, 부모 이동, 풀링, 밀집 시 순차 전환 및 다음 스텝의 트리 갱신을 비교한다. 벤치마크 자체도 결과와 이미지 동등성을 검사한다.

최종 Release 전체 빌드 성공. 전체 44개 테스트 통과를 확인했다. 제한된 실행 환경에서는 40개가 통과했고, Windows 레지스트리/파이프 접근과 하위 빌드가 필요한 DataRoutingCompileContract, ControllerModel, ControllerIntegration, PlayerMediaIntegration 4개는 제한을 해제한 재실행에서 통과했다.

전체 빌드 중 기존 InstancingBenchmark의 routed field 사용에 필요한 RiceData 링크 누락도 함께 수정했다.
